## 1. 画面共有うっかり番

- カテゴリ: Browser Extension
- 対象ユーザー: リモート会議で頻繁に画面共有するエンジニア・PjM
- 一行で: 画面共有を始める瞬間に開いているタブを検問して機密っぽいタブがあれば警告してくれるのだ

### 解決する痛み

画面共有しながら資料を説明していると、裏で開いていた給与明細タブや個人のDM、社外秘の契約書PDFが視界に入ってヒヤッとする瞬間がある。共有前に毎回全タブを目視確認するのは面倒で、慌てているときほど忘れがち。Zoom/Meetの「ウィンドウ単位共有」を使えば防げるが、つい全画面共有を選んでしまい素通りしてしまう。共有が始まる瞬間に機械的にチェックしてくれるだけで事故はかなり減る。

### 1 週間で作るならこれ

- `getDisplayMedia()` の呼び出しをcontent script + backgroundで検知し、画面共有開始のタイミングを捕捉
- 開いている全タブのタイトル・URLを走査し、キーワードリスト（給与、契約書、個人情報、bank等）に一致したら警告バナーをオーバーレイ表示
- 警告バナーは「共有を続ける / 該当タブを閉じてから共有する」の2択のみ提示
- キーワードリストは設定画面でユーザーがカンマ区切りで追加・編集できる
- 検知ログはローカル保存のみで外部送信はしない

### なぜ雑か

実際の画面内容（ピクセル）は見ず、あくまでタブのタイトル・URL文字列マッチのみなので誤検知・見逃しは普通にある。Zoom/Meet以外の会議ツールでの`getDisplayMedia`呼び出しは個別動作確認していないベストエフォート対応。キーワード辞書は日本語・英語の主要ワードのみで多言語非対応。共有開始後に新しいタブを開いた場合の追跡はせず、共有開始の瞬間の1回チェックのみ。

### 雑な技術スタック候補

Chrome Extension (Manifest V3) + chrome.tabs API + content script (getDisplayMedia フック) + chrome.storage.sync

## 2. 有給とったもん勝ち

- カテゴリ: Bot (Slack)
- 対象ユーザー: 有給消化率が低いメンバーを多く抱える労務担当・チームリード
- 一行で: 有給消化ペースが遅い人にだけそっとSlackでリマインドしてくれるのだ

### 解決する痛み

有給休暇は年5日以上の取得が求められているのに、日々の忙しさにかまけて後回しにし、気づけば年度末に慌てて消化する人が毎年出る。労務担当は台帳を見ながら個別に声をかけるのが面倒で、結局「有給を計画的に取りましょう」という全体周知メールで済ませがちだが、自分ごと化されず誰にも刺さらない。本人にだけそっと「今年あと何日残ってます」と伝われば、計画的に休みを取る後押しになる。

### 1 週間で作るならこれ

- 各メンバーが入社日と年間付与日数をGoogle Sheetに登録
- 月初にSheetの「今年度消化日数」列を読み込み、経過月数に対する消化ペース（経過月数/12 × 付与日数）と比較
- ペースが遅い人にだけ本人限定DMで「有給、今年あとN日残ってます」と通知
- 消化日数の更新はSlackスラッシュコマンド `/pto 1` で本人が自己申告して更新
- 労務担当向けに全体の消化率サマリーを毎月1回だけ別チャンネルに投稿

### なぜ雑か

有給申請システムとは連携せず全て自己申告ベースなので、申告漏れや誤入力があっても検知できない。半休・時間単位有給は考慮せず1日単位でしか数えない。祝日・会社カレンダーとの連動はなく、消化ペースの目安も単純な線形按分のみ。入社1年未満の比例付与計算は考慮せず、全員フル日数で計算する簡易実装のまま。

### 雑な技術スタック候補

Slack Bolt (Node.js) + Google Sheets API + node-cron (月初バッチ) + Slack slash command

## 3. スタックトレース道場

- カテゴリ: 学習ツール (Web)
- 対象ユーザー: エラーログを見ても「どこから読めばいいか分からない」新人エンジニア
- 一行で: 実際のスタックトレースを見せて根本原因の行を当てるクイズで読解力を鍛えるのだ

### 解決する痛み

新人エンジニアはエラーが起きたとき、真っ赤なスタックトレースを上から下まで全部読もうとして時間を溶かし、結局「動きません、エラーはこれです」とだけ先輩に丸投げしてしまう。実は「どのフレームが自分のコードか」「どこが本当の発生源か」を素早く見分けるコツがあるのに、体系的に練習する機会がない。実例で繰り返し練習すれば、数をこなすほど読むスピードが上がる。

### 1 週間で作るならこれ

- Python/JS/Java別に、実際にありそうなスタックトレース例（自作＋OSSのエラーを匿名化したもの）を50問ストック
- 1問ずつトレース全文を表示し、「原因の行はどれ？」をハイライトされた4択から選ばせる
- 正解・不正解どちらでも「なぜここが原因か」の1〜2行解説を表示
- 正答率と平均回答時間をローカルストレージに記録し、マイページで推移をグラフ表示
- 言語別（Python/JS/Java）にフィルタして出題できるセレクタ

### なぜ雑か

出題は50問固定のストック問題のみで自動生成はせず、増やすには手動でJSON追加が必要。ユーザーが自分のログを投げ込んで問題化する機能はない。苦手分野を重点出題するようなアダプティブ学習はせず、単純なランダム出題のまま。ログイン機能はなくブラウザのlocalStorageのみで進捗管理するので、端末を変えると記録は消える。

### 雑な技術スタック候補

Next.js (静的サイト) + JSON問題データ + localStorage (進捗保存) + Recharts (推移グラフ)
