## 1. PR重量計

- カテゴリ: CLI
- 対象ユーザー: OSSメンテナ・社内リポジトリでPRレビューを担当するエンジニア
- 一行で: PRのdiffを渡すだけで推定レビュー所要時間を計算してデカすぎるPRに警告してくれるのだ

### 解決する痛み

レビュー依頼のSlack通知が来ても、開いてみるまで規模が分からず、変更ファイル50個・追加行数800行のPRだったりすると「今日中には見れない」と分かった時点で結局後回しにしてしまう。作成者側も、自分のPRがどれくらいレビュアーの時間を奪うか自覚がないまま巨大なまま提出しがちで、レビューが1週間放置される原因になる。事前に規模と推定所要時間が分かれば、レビュアーはタイムボックスを確保できるし、作成者は分割を検討するきっかけになる。

### 1 週間で作るならこれ

- `prweight <PR番号 or diffファイル>` でGitHub CLI経由もしくはローカルdiffを読み込み
- 変更ファイル数・追加/削除行数・変更言語の内訳を集計
- 行数×言語別の経験則係数（ロジック変更ファイルは重み増し）で「推定レビュー時間」を算出
- 閾値（例: 30分超）を超えたら赤字で警告、GitHub Actionsとして動かせばPRコメントに自動投稿
- 結果をJSON出力してSlack通知などに繋げられるようにする

### なぜ雑か

推定時間の係数は完全に経験則の固定値で、チームやコードベースごとのチューニングは不可。テストファイルやロックファイルの除外設定は決め打ちで柔軟にできない。依存関係や複雑度（循環的複雑度など）は見ない、純粋な行数ベース。複数言語混在時の重みは平均するだけの雑実装。

### 雑な技術スタック候補

Node.js + GitHub CLI (gh) + simple-git (diff parse) + GitHub Actions (comment post)

## 2. ミュート丸わかりランプ

- カテゴリ: ガジェット
- 対象ユーザー: 毎日複数のオンライン会議に出るリモートワーカー
- 一行で: 会議アプリのミュート状態を卓上の大きなランプでド派手に光らせてくれるのだ

### 解決する痛み

Zoom・Meetのミュートアイコンは画面の隅に小さく表示されるだけなので、画面共有に集中していたり資料を見ながら話していると気づかず「すみません、ミュートでした」を何度も繰り返してしまう。逆にミュートのつもりで実は喋りっぱなしで、隣室の生活音やタイピング音を会議に流してしまうことも多い。視界の端に置ける物理的な光であれば、画面を見ていなくても一瞬で状態が分かる。

### 1 週間で作るならこれ

- ESP32 + フルカラーLEDリング（またはRGB LEDテープ）を卓上スタンドに組み込む
- PC側の常駐スクリプトがZoom/Meetのミュート状態をOSのマイク使用中フラグで判定
- ミュート中は赤、発言可能な状態は緑にWi-Fi経由でLEDへ状態をPOST
- ミュート状態が5分以上続いたら自動でゆっくり点滅させて「発言できないままだよ」を注意喚起
- Webブラウザからランプの明るさと点灯パターンを設定できる簡易設定画面

### なぜ雑か

実際に「ミュートなのに喋っている」の音声検出はせず、OS側のマイクフラグのみを見るので、アプリ側の内部ミュート（Zoom独自の追加ミュート機能等）には対応しない。対応アプリはZoomとGoogle Meetのみ、他の会議ツールでは動作しない。複数モニター・複数会議アプリ同時起動時はどちらの状態を拾うか未定義。ケースは3Dプリンタの雑な出力そのままで見た目は気にしない。

### 雑な技術スタック候補

ESP32 + WS2812B LEDリング + Python常駐スクリプト（プロセス監視） + HTTP POST + Flask簡易設定画面

## 3. 優先度たいけつくん

- カテゴリ: 業務ツール (Web)
- 対象ユーザー: バックログの優先順位付け会議が長引くプロダクトチーム・PjM
- 一行で: タスクを2択でどんどん対決させるだけでチームの優先順位ランキングが勝手にできあがるのだ

### 解決する痛み

スプリント計画の場でバックログを1件ずつ「これ先にやる?後でいい?」と議論すると、声の大きい人の意見が通りがちで、結局優先順位は誰かの主観のまま決まってしまう。Notionやスプレッドシートで手動ドラッグ&ドロップして並べ替えるのも面倒で、途中でみんな飽きて更新が止まる。全員が非同期にサクッと投票できて、勝手にランキングが積み上がる仕組みがあれば、会議時間を溶かさずに済む。

### 1 週間で作るならこれ

- バックログのタスク名をテキストエリアに改行区切りで貼り付けて一括登録
- ランダムに2件のタスクをペア表示し「どっちを先にやる?」ボタンをワンクリックで投票
- 投票結果からELOレーティングのような簡易スコアを計算してリアルタイム更新
- 投票用URLをSlackに貼るだけでチームメンバーが匿名でどんどん投票できる
- 一定投票数に達した時点の優先順位ランキングをMarkdownでコピーできるボタン

### なぜ雑か

タスク間の依存関係（このタスクが終わらないと着手できない、等）は一切考慮しない。投票の重み付け（役職・担当領域による）はなく、全員1票で平等。同点になった場合はタスク登録順で雑に決着させる。認証機能はなくURLを知っていれば誰でも何回でも投票できてしまう（自作自演対策なし）。

### 雑な技術スタック候補

Next.js + Supabase (タスク・投票データ) + クライアントサイドELO計算 + Vercelホスティング
