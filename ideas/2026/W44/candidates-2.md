## 1. CHANGELOG置き去り検知くん

- カテゴリ: CLI
- 対象ユーザー: OSSメンテナー・ライブラリ作者でリリース時にCHANGELOG.mdの更新を忘れがちな人
- 一行で: バージョンタグを打つだけでCHANGELOGの更新漏れを教えてくれるのだ

### 解決する痛み

バージョンタグを打つたびにCHANGELOG.mdへの追記を忘れ、ユーザーに「このバージョンで何が変わったか」を聞かれてから慌てて書く。直接代替はrelease-itやchangesetsのようなリリース自動化ツールだが、どれも「CHANGELOGを書く運用を徹底する」ための仕組みであって「書き忘れた事実そのものを検知して教えてくれる」ものではなく、結局書く人の意識に依存したままになっている。

### 1 週間で作るならこれ

- git tagとpackage.json/Cargo.tomlのバージョン文字列、CHANGELOG.md内の見出し(## [x.y.z])を突き合わせる単一のコアフローだけを作る
- バージョンが上がっているのにCHANGELOGエントリがないタグを一覧表示
- CHANGELOGにあるのに対応するタグが存在しないエントリも警告
- 設定ファイルや複数フォーマット対応はせずKeep a Changelog形式のみ固定
- CHANGELOG更新を1件だけわざと忘れたサンプルリポジトリを用意し、`npx this-tool` を叩くと30秒以内に欠落バージョンが赤字で出るデモで価値を見せる

### なぜ雑か

モノレポの複数パッケージには非対応で1リポジトリ1バージョンのみ想定。日付の整合性チェックはせずバージョン番号の有無だけを見る。これは需要確認済みの機能ではなく仮説段階で、GitHub Actions Marketplaceに公開して実際のメンテナが検索で見つけて導入してくれるか（配布先の到達可能性）は未検証の課題として残す。

### 雑な技術スタック候補

Node.js CLI + commander + semver + simple-git + GitHub Actions (composite action) + npx配布

## 2. 20-20-20アイセイバー

- カテゴリ: ガジェット
- 対象ユーザー: 長時間ディスプレイを見続けるエンジニア・デザイナーで目の疲れに悩む人
- 一行で: 机に置くだけで20分ごとにやさしく光って「20フィート先を20秒見て」と教えてくれるのだ

### 解決する痛み

ディスプレイを見続けて気づいたら2時間経ち目が疲れている。眼科医が勧める20-20-20ルール（20分おきに20フィート先を20秒見る）は知っていても実践できない。直接代替はスマホのリマインダーアプリだが、通知が画面に出るのでそのまま画面を見続けてしまい、休ませるはずの目をさらに使ってしまう逆効果が起きている。画面の外に置く物理デバイスでないと視線を外すきっかけにならない。

### 1 週間で作るならこれ

- ESP32とタイマーだけで20分経過を検知してLEDを点灯させる単一のコアフローだけを作る
- 20分経過するとリング状LEDがゆっくり点灯し画面から視線を外すよう知らせる
- 20秒経過後LEDが消灯し次の20分カウントを自動で再スタート
- 離席検知やスマホ連携はせず単純なタイマーループのみ
- タイマーを60倍速（20分→20秒、20秒→0.3秒）にしたデモモードを仕込み、30秒以内に一連の点灯サイクルを見せられるようにする

### なぜ雑か

離席中もタイマーは進み続け在席センサーは付けない。複数人のデスクがある場では個人ごとの調整ができず1台1人前提。20分という間隔は固定でコード内の定数書き換えが設定変更の手段になる。これは「物理デバイスの方がスマホ通知より目を休ませる効果が高い」という仮説段階のプロダクトであり、実際に継続して使われるか・配布サイトでどこまで到達できるかは検証していない課題として残す。

### 雑な技術スタック候補

Arduino IDE + ESP32（Wi-Fi機能は使わない） + WS2812 LEDリング + タクトスイッチ + USB給電ケース

## 3. ポストモーテム抜き打ちテスト

- カテゴリ: 学習ツール (Web)
- 対象ユーザー: スタートアップのオンボーディング担当・新しく入ったエンジニア
- 一行で: 過去のインシデント報告書を貼るだけで新人向けの原因当てクイズを自動で作ってくれるのだ

### 解決する痛み

チームに溜まった過去のインシデントのポストモーテムを新人に読ませても流し読みで終わり、「なぜあの障害が起きたか」というtribal knowledgeはベテランの退職と共に失われていく。直接代替はオンボーディング資料として一覧を渡すか先輩が口頭で話すことだが、どちらも「読んだ/聞いた」で終わり定着度を確認する仕組みがない。

### 1 週間で作るならこれ

- ポストモーテムのテキストを貼ると原因部分を伏せ字にした4択クイズをAIが生成する単一のコアフローだけを作る
- 出題後、正解すると該当箇所をハイライトした全文を公開
- 間違えた問題だけを後で再挑戦できるリストを表示
- 複数人同時プレイやランキング機能は作らない
- 実際の過去インシデント1件を貼ってクイズが生成され解答・ハイライト表示まで一連の流れを30秒以内に見せるデモを用意する

### なぜ雑か

AIが生成する選択肢の精度は保証せずたまに的外れな問題が混ざる前提。機密情報が混入しないかのチェックは人間が貼る前に行う前提で自動マスキングはしない。これはポストモーテムをクイズ化すれば定着率が上がるという仮説段階の施策であり、社内ツールとして実際に新人が使い続けてくれるかは検証していない課題として残す。

### 雑な技術スタック候補

Next.js + Supabase（保存・認証） + OpenAI API（クイズ生成） + Vercel
