## 1. PingMate

- カテゴリ: Bot (Slack)
- 対象ユーザー: 非同期リモートワーク中のチームメンバー・チームリード
- 一行で: 集中中かどうかをSlackに宣言、DM前に一秒確認

### 解決する痛み

フルリモートチームで「今この人に聞いていいの?」という判断が毎回難しい。DM を送ったら「実は集中タイム中だった」と申し訳なく思うし、送らなければブロッカーが何時間も解消されない。Slack のカスタムステータスは更新を忘れがちで形骸化し、カレンダーを覗く方法は相手に気まずさを感じる。「今は話しかけて OK か NG か」だけを 1 コマンドで宣言・確認できれば、チームの摩擦が消える。

### 1 週間で作るならこれ

- `/pingmate busy 2h` でビジー宣言、時間経過で自動解除
- `/pingmate @user` でその人の現在状態と「いつ空くか」を即確認
- 誰かがビジー中の人を @mention したら本人に代わって Bot が「15:00 まで集中中です」と自動返信
- `/pingmate team` でチームの今日の可用性タイムラインを一覧表示
- 宣言し忘れ防止: 朝 9 時にチャンネルへ「今日のステータスを設定してください」リマインダー

### なぜ雑か

カレンダー連携なし・自己申告制なので更新を忘れたら終わり。複数ワークスペースへの OAuth 配布なし、自チームへの手動インストールのみ。タイムゾーンは手動設定でサマータイム未考慮。ステータス履歴の保存は 24 時間分のみ。

### 雑な技術スタック候補

Bolt for JS (Slack SDK) + Vercel Serverless Functions + Vercel KV (Redis で状態管理)

## 2. fixture-gen

- カテゴリ: CLI
- 対象ユーザー: テストデータを手で書いている Node.js / Python バックエンド開発者
- 一行で: JSON Schema を渡したらリアルなダミーデータが100件即出る

### 解決する痛み

新しい API エンドポイントを作るたびに `"name": "test"` / `"email": "test@example.com"` という嘘くさいシードデータを手で書く作業が発生する。Faker ライブラリは知っているが、スキーマ定義から手動で `faker.internet.email()` を対応付けるコードを書くのが面倒。結果として 3 件しかシードデータがなくてページングのバグに気づかなかったり、実データっぽくないせいで UI が崩れていたりする。

### 1 週間で作るならこれ

- `fixture-gen schema.json -n 100` で JSON Schema draft-7 から 100 行のダミーデータを生成
- フィールド名から自動推測: `email` → 有効なメアド、`age` → 18-80 整数、`url` → 有効 URL、`phone` → 電話番号形式
- 出力フォーマット: JSON 配列 / NDJSON / SQL INSERT 文 の 3 択
- `--seed 42` で決定論的出力 (スナップショットテストに使える)
- `--locale ja` で日本語ダミーデータ (名前・住所・会社名)

### なぜ雑か

`$ref` の再帰解決は 3 階層まで。`oneOf` / `anyOf` / `not` は未対応でスキップ。ネスト配列の要素数は min/maxItems を無視して 1-3 件固定。TypeScript interface は読めない (JSON Schema 変換は自分でやってほしい)。バリデーションエラーのメッセージは素っ気ない。

### 雑な技術スタック候補

Node.js + @faker-js/faker + Ajv + commander.js、npm publish で `npx fixture-gen` 即使用可能

## 3. diff-quiz

- カテゴリ: 学習ツール
- 対象ユーザー: コードレビュー力を上げたいジュニア〜ミッドレベルのエンジニア
- 一行で: 実際のOSSバグ修正diffを見て「何が悪かった?」を当てるクイズ

### 解決する痛み

コードレビューの力は他人のコードを読む経験で身につくが、「読むだけ」ではフィードバックがないので伸び方が曖昧。「他人のPRを読め」と言われても何に注目すればよいか分からず、自分が何を見落としているかも分からない。実際のバグ修正 diff を題材に「ここが問題だった」を当てるクイズ形式なら、答え合わせで自分の盲点が具体的に分かる。

### 1 週間で作るならこれ

- React / CPython / Rails などの著名 OSS から厳選した実際のバグ修正 diff を 25 問用意
- `git diff` 形式で問題を表示し「元コードのどこが問題か?」を 4 択で回答
- 正解後に実際のコミットメッセージ・リンクしていた Issue を表示 (「なぜこれがバグだったか」の解説)
- localStorage でスコア記録 + 「あなたが見落としやすいバグカテゴリ TOP 3」集計
- 問題にタグ付け: off-by-one / null check / race condition / typo / security など

### なぜ雑か

問題は 25 問のハードコード JSON で自動追加なし。無限モードは実装しない。ユーザーアカウントなし・スコア共有不可。diff が長い問題 (100 行超え) は適当にトリミングしてあるため前後のコンテキストが欠ける場合あり。

### 雑な技術スタック候補

Vite + React + Tailwind CSS + ハードコード JSON データセット、GitHub Pages で無料ホスト・ビルド成果物を push するだけ
