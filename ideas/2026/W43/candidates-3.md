## 1. 返信テンプレ事故防止くん

- カテゴリ: Browser Extension
- 対象ユーザー: 複数クライアントに似た文面のメールを使い回すフリーランス・代理店担当者
- 一行で: 送信ボタンを押す前に本文中の会社名と宛先ドメインのズレを検知して止めてくれるのだ

### 解決する痛み

複数クライアントを並行してやり取りしていると、前のメールをコピーして書き直す際に宛名や社名だけ直し忘れて別の会社名のまま送ってしまう事故が起きる、というのはよくある失敗談だが、実際にどの頻度で発生していて信頼関係にどれほど響いているのかはまだ確認できていない仮説である。送信直後に「あ、A社宛なのにB社の名前が残ってる」と気づいて冷や汗をかく場面を想定している。Gmailで下書きを使い回す人に絞って検証したい。

### 1 週間で作るならこれ

- 送信先メールドメインと、事前にユーザーが登録した「ドメイン⇔会社名」対応表を照合する単一のコアフローだけを作る
- 本文中から固定パターン（「株式会社◯◯」「◯◯様」等）で会社名らしき文字列を抽出し、送信先ドメインの会社名と一致しないものがあれば送信ボタン直前にポップアップ警告
- 対応表はユーザーがクリックで1件ずつ手動登録（自動名寄せはしない）
- 誤って他社名が混入した合成サンプルメールを1クリックで読み込める「デモを試す」ボタンを用意し、警告が出るまでを30秒以内に体感できるようにする
- 対応はGmail(Web版)限定、Outlook・他のメーラーは対応しない

### なぜ雑か

会社名の表記揺れ（Inc./株式会社/有限会社など）は一部パターンしか拾えず誤検知・見逃しがあり得る。CCやBCCに紛れた別会社の文脈までは追わない。Grammarlyのようなツールは文法・トーンは見るが宛先との整合性チェックは行わない直接代替であり、本プロダクトはその隙間を狙うだけで、実際に需要があるかは未確認。配布先としてChrome Web Storeやフリーランス向けコミュニティを想定しているが、そこに実際に対象ユーザーが来てインストールしてくれるかという到達可能性は検証していない課題として残す。

### 雑な技術スタック候補

Chrome Extension (Manifest V3) + Gmail DOM監視 + chrome.storage（対応表の保存）

## 2. 推し新刊リリース番人

- カテゴリ: Bot (Discord)
- 対象ユーザー: 複数の漫画・ライトノベルシリーズを追いかけている読書コミュニティのDiscordサーバー運営者・メンバー
- 一行で: 作品名を登録するだけで新刊の発売日が近づくとDiscordチャンネルに自動で教えてくれるのだ

### 解決する痛み

好きなシリーズを何本も追いかけていると発売日がバラバラで、書店に行って「もう出てたんだ」と後から気づくことがある、というのはよくある体験談だが、それがどれだけの頻度で起きていて実際に購買行動にどう影響するのかはまだ確認できていない仮説である。Amazonの予約通知はシリーズごとに毎回設定する手間があり、読書コミュニティのDiscordサーバーで「今月何が出るんだっけ」と毎回誰かが手動で調べて共有している場面を想定している。

### 1 週間で作るならこれ

- Discordのスラッシュコマンドで作品名を登録するだけの単一のコアフローだけを作る
- 書誌情報API（openBD等）を1日1回ポーリングし、登録済み作品の次回発売日を取得
- 発売1週間前と当日にチャンネルへ自動投稿で通知
- 人気シリーズ3件を登録済みにした「デモサーバー構成」をコマンド一発で読み込み、次回発売日の通知が流れるまでを30秒以内に体感できるようにする
- 対応は書籍（漫画・ライトノベル）限定。音楽・ゲーム・映画・同人誌は対応しない

### なぜ雑か

情報源は単一の書誌データベースのみに依存し、そこに載らないタイトルや表記揺れがあるタイトルは検知できず、該当時はユーザーが候補から手動選択する必要がある。巻数ごとの個別管理はせず「このシリーズの次の巻」という粒度のみ対応。Amazonのお気に入り登録や出版社公式X（旧Twitter）のフォローが既に直接代替として存在するが、複数シリーズを一つのチャンネルに集約できる点が差分であり、それ自体に需要があるかは未確認。配布先として読書系Discordコミュニティへの口コミを想定しているが、実際にそこへ到達できるかは検証していない課題として残す。

### 雑な技術スタック候補

Node.js + discord.js + openBD API + node-cron

## 3. 楽器練習ログ採点くん

- カテゴリ: 学習ツール (Web)
- 対象ユーザー: 先生に付かず独学でピアノ・ギターを練習している初心者
- 一行で: 練習を録音するだけでテンポの安定度を先週分と比べて見せてくれるのだ

### 解決する痛み

独学で楽器を練習していると、自分の演奏が上達しているのか停滞しているのか客観的に分からず、モチベーションが続かない、というのはよくある悩みだが、実際にテンポの安定度という単一指標の提示だけで練習継続につながるかはまだ確認できていない仮説である。「今日の練習、先週より良くなった気がするけど分からない」という場面を想定し、音程やリズムの正誤判定ではなく「揺れの少なさ」だけに絞って検証したい。

### 1 週間で作るならこれ

- ブラウザのマイクで演奏を録音し、オンセット検出（音の立ち上がり）からテンポの揺れ幅を数値化する単一のコアフローだけを作る
- 同じ曲を登録した上で録音を重ねると、直近の揺れ幅を前回・前々回と並べて折れ線で表示
- 曲ごとに練習回数と録音日だけをシンプルなリストで記録
- 「上手な演奏」「テンポが揺れている演奏」のサンプル音声2本を読み込める「デモを聴く」ボタンを用意し、指標の差が30秒以内に見えるようにする
- 音程の正誤判定・採点コメント生成はしない。テンポの安定度のみを扱う

### なぜ雑か

曲の難易度やジャンルによる基準の違いは一切考慮せず、全曲一律の指標で揺れ幅を出すだけ。伴奏とのズレや強弱表現の評価もしない。YousicianやSimply Pianoのような音楽教育アプリは音程・リズムまで含めた正式な採点を既に提供する直接代替だが、本プロダクトは録音だけで雑にテンポ安定度だけを見る軽量版と位置づけ、そもそも需要があるかは未確認。配布先として楽器練習系SNSコミュニティでの共有を想定しているが、実際に到達できるかは検証していない課題として残す。

### 雑な技術スタック候補

Next.js + Web Audio API + essentia.js（オンセット検出） + Chart.js
