## 1. レビュー偏り白状くん

- カテゴリ: 業務ツール (Web)
- 対象ユーザー: 複数人でPRレビューをしているチームのテックリード・EM
- 一行で: GitHubのリポジトリ名を渡すだけで誰がレビューを負担しすぎているか一覧にしてくれるのだ

### 解決する痛み

レビューが得意な人やレスポンスが早い人にPRが集中し続けていく。「〇〇さんに頼めば早い」という口コミが積み重なった結果、特定の1〜2人が全PRの半分以上をレビューしている状態が放置されがちだ。マネージャーは各人のレビュー数や時間を手で数える気力がなく、偏りがどの程度深刻か定量的に把握していないまま1on1を迎える。実際にどれだけ偏りがチームの疲弊に直結しているかは検証済みの知見ではなく仮説であり、直接代替は各人がGitHub Insightsのcontributorsタブを個別に開いて目で数える手作業しかない。

### 1 週間で作るならこれ

- GitHub OAuthでリポジトリを1つ選び、過去4週間分のPRレビュー履歴を取得する単一コアフロー
- レビュー担当者ごとにレビュー回数・コメント数・レビュー依頼からの応答時間を集計してランキング表示
- 合成デモ用に5人×50PR分のダミーデータを同梱し、リポジトリ名を入れた画面から30秒以内に偏りランキングが出る体験を用意する
- 上位1人がレビュー総数の何%を占めているかだけを強調表示（詳細な時系列グラフは作らない）
- 対象は1リポジトリ・直近4週間固定、複数リポジトリ横断や期間変更は未対応

### なぜ雑か

Organizationをまたいだ複数リポジトリの集計は対応しない。レビューの質（的確さ）は一切評価せず回数と応答時間だけを見る。Dependabotなどのbotによる自動レビューを人間と区別せず混入する可能性がある。社内の複数チームへどう広げるかという配布経路は確認課題として残す。

### 雑な技術スタック候補

Next.js + GitHub REST API (Octokit) + Vercel + SQLite（ローカルキャッシュ）

## 2. 交代ベル

- カテゴリ: デスクトップアプリ
- 対象ユーザー: モブプロ・ペアプロでドライバー/ナビゲーターの交代忘れが多発する開発チーム
- 一行で: メンバーリストを登録するだけで決めた間隔で「次は誰?」とデスクトップに大きく知らせてくれるのだ

### 解決する痛み

ペアプロやモブプロで「10分交代」と決めても作業に没頭すると誰も時間を見ておらず、気づいたら1人が40分キーボードを握り続けている。交代が偏ると発言の少ないメンバーがどんどん置いていかれる感覚を覚えるが、これがどの程度チームの学習効果を下げているかは未検証の仮説にすぎない。直接代替はスマホのタイマーを別途セットする方法だが、画面共有中にタイマーだけ別ウィンドウで管理するのが地味に面倒で誰も続けない。

### 1 週間で作るならこれ

- 参加者の名前を順番に登録し、交代間隔（5/10/15分から選択）を設定する単一コアフロー
- タイマーが切れたら画面全体に次のドライバー名を数秒間オーバーレイ表示してベル音を鳴らす
- ダミーの4人ローテーションで即スタートできる合成デモを用意し、起動から30秒以内に最初のベルが鳴る体験を見せる
- 現在の順番と残り時間だけをメニューバー/タスクトレイに常時表示
- 交代履行の記録やSlack通知などの付加機能は作らない

### なぜ雑か

画面共有アプリとの連携はせず自分のPC上のオーバーレイのみ。離席や早退があった場合の順番スキップは手動操作が必要。チーム外のメンバーをどう招待して複数チームに配布するかは確認課題として残す。

### 雑な技術スタック候補

Electron + ローカルJSON保存 + システム通知API

## 3. 蛍光ペン定着くん

- カテゴリ: 学習ツール (モバイル PWA)
- 対象ユーザー: 本にマーカーを引いても読み返さず内容を忘れていく読書好き
- 一行で: ハイライトしたページを撮るだけで数日後に間隔を空けてクイズ形式で聞いてくれるのだ

### 解決する痛み

本を読みながら「これは大事」と思ってマーカーを引いた箇所が、読み終えた瞬間から記憶に残らず本棚の奥に沈んでいく。読書メモアプリはテキスト転記が面倒で続かず、結局ハイライトした事実だけが本に残る。ハイライトの再提示が記憶定着に効くという前提は検証済みの効果ではなく仮説であり、直接代替はNotionやEvernoteに手で書き写して時々見返す方法だが、転記の手間自体が最大の離脱要因になっている。

### 1 週間で作るならこれ

- ハイライトしたページをスマホで撮影しOCRで該当行っぽいテキストを抜き出す単一コアフロー
- 抜き出した一文を3日後・7日後・21日後の3回だけ「このフレーズの続きは?」という穴埋めクイズとして通知
- 合成デモ用に3冊分のダミーハイライト画像を同梱し、撮影から30秒以内に最初のクイズカードが生成される体験を用意する
- 答え合わせは自己採点（○/×ボタン）のみで厳密な正誤判定はしない
- 書籍情報の自動識別（ISBN検索など）はせず手入力のタイトルのみ

### なぜ雑か

OCRの誤読はそのまま出題文に混入する前提で補正はしない。間隔反復のアルゴリズムは3段階固定でAnki的な動的調整はしない。個人の読書記録にとどめ、不特定多数への配布導線（アプリストア公開など）は確認課題として残す。

### 雑な技術スタック候補

Expo (React Native) + expo-camera + Google Cloud Vision API (OCR) + ローカルSQLite + Expo Notifications
