## 1. nit埋もれ救済くん

- カテゴリ: Browser Extension
- 対象ユーザー: 大きめのPRを出して20件以上レビューコメントを受け取るエンジニア（特にジュニアや新規参加者）
- 一行で: PRのレビューコメントを貼るだけで「本当に直すべき指摘」だけのチェックリストにしてくれるのだ

### 解決する痛み

GitHubのPRに20件以上のレビューコメントが並ぶと、スタイルの好みを指摘する「nit」と本当に直さなきゃいけない指摘が混在していて、どれを先に直すべきか分からず結局全部後回しにしてしまう。レビュアーも毎回「nit:」と書くのを忘れるし、書く人によって粒度もバラバラ。結果、重要な指摘がコメントの山に埋もれたままCIだけ通してマージしてしまい、後で気づいて気まずくなる。

### 1 週間で作るならこれ

- Chrome拡張がGitHub PRの「Conversation」「Files changed」タブを検知
- 各レビューコメント本文をAPIに送って「blocking / suggestion / nit」の3段階に自動ラベル付け
- サイドバーに「blocking」だけを抜き出したチェックリストを表示、クリックで元コメントまでスクロール
- チェックした項目はブラウザの`chrome.storage.local`でPR単位に既読管理
- 誤分類だけ手動でラベルを上書きできるボタンを1個だけ用意

### なぜ雑か

複数ファイルにわたる文脈は読まずコメント本文だけでAIが判定するので誤分類はそこそこ起きる前提。GitHub以外（GitLab、Bitbucket）は未対応。チームごとのラベル規約には合わせない。既読状態は端末ローカルのみでチームメンバー間の共有はしない。コメントスレッドが解決済みかどうかの判定は別領分として今回は見ない。

### 雑な技術スタック候補

Chrome Extension (Manifest V3) + GitHub REST API + OpenAI API (3値分類) + chrome.storage.local

## 2. 物干しレスキュー番

- カテゴリ: ガジェット
- 対象ユーザー: 在宅勤務や外出中にベランダ・庭で洗濯物を干している人
- 一行で: ベランダに置くだけで雨が来そうなら洗濯物SOSをLINEで教えてくれるのだ

### 解決する痛み

洗濯物を外に干して出かけたあと、天気予報が急変してにわか雨が降り出すことがよくある。天気アプリの通知をオンにしても他の通知に埋もれて見逃し、帰宅して初めて洗濯物が濡れているのに気づく。濡れた分をもう一度洗い直すのは地味に時間とストレスを食う。

### 1 週間で作るならこれ

- ベランダに置く小型デバイス（ESP32 + 雨滴センサー + 湿度センサー）が降雨の有無を検知
- 1時間おきに気象APIを叩いて「1時間以内の降水確率」も合わせてチェック
- センサーが雨を検知、または予報が閾値を超えたらLINE Notifyで「洗濯物やばいかも」と通知
- 干し始めにスマホから1タップで「干し中」フラグをON、取り込んだら1タップでOFF（OFFなら通知を止める）
- 誤報を減らすため通知は1日1回のクールダウン付き

### なぜ雑か

雨滴センサーだけでは実際に洗濯物が濡れたかどうかは確定できず、あくまで確率ベースの推測。ベランダの向きや屋根の有無でセンサー感度が全然変わるので個体ごとの手チューニングが前提。複数世帯分のベランダには対応せず1台=1ベランダ固定。雨の日のデバイスの防水はジップロックで済ませる。

### 雑な技術スタック候補

ESP32 + 雨滴センサーモジュール + DHT22 + OpenWeatherMap API + LINE Notify API + Arduino IDE

## 3. ネタ被り検知くん

- カテゴリ: Web (AI ツール)
- 対象ユーザー: Qiita・Zenn・個人ブログ・Xスレッドなどで定期的に技術記事を書いている個人エンジニア
- 一行で: 下書きを貼るだけで過去に書いたネタと被ってないか教えてくれるのだ

### 解決する痛み

「このネタ前にも書いた気がする」と思いながらも過去記事を全部読み返す気力がなく、結局似た内容を数ヶ月おきに書いてしまう。読者に「これ前と同じ話では」と思われていないか不安が残るし、過去記事一覧をスプレッドシートで手動管理する習慣も長続きしない。

### 1 週間で作るならこれ

- QiitaのRSSやZennのプロフィールURLを貼ると過去記事のタイトルと冒頭を取得して保存
- 新しく書きたい記事の下書き（タイトル＋要約）を貼ると保存済みの過去記事と類似度を計算
- 類似度が高い記事を上位3件、スコア付きで一覧表示
- 「これは別角度だから出す」ボタンで判定結果だけ記録（除外はしない、記録のみ）
- 公開済みの新規記事を「公開済み」として保存プールに追加

### なぜ雑か

類似度計算は本文全部ではなくタイトルと冒頭300文字のみで行うので、中身が違っても表現が似ていると誤検知する。RSSのないブログや英語記事には対応しない（日本語＋RSS対応プラットフォームのみ）。類似記事が見つかっても「どう変えるべきか」の提案まではしない、気づかせるだけに留める。

### 雑な技術スタック候補

Next.js + OpenAI Embeddings API + Supabase (pgvector) + rss-parser + Vercel
