## 1. 塩漬けフラグハンター

- カテゴリ: CLI
- 対象ユーザー: feature flagを大量に運用していて削除忘れが溜まっているプロダクトチームのエンジニア
- 一行で: フラグ管理サービスのAPIを叩くだけでrollout率が固定されたまま放置されたフィーチャーフラグをランキングしてくれるのだ

### 解決する痛み

新機能のABテストやカナリアリリースのたびにフラグを増やしていくが、100%や0%で固定されたまま誰も消しに来ないフラグがコードベースに何十個も積み上がる。`if (flags.newCheckout)` のようなif文が延々と残り、新人は「このフラグ今も意味あるんですか」と聞いて回る羽目になる。削除していいかの判断材料（いつから変化していないか、コード中で何行に絡んでいるか）がバラバラに散らばっていて、結局誰も手を付けずに放置される。

### 1 週間で作るならこれ

- LaunchDarkly / Unleash のREST APIからフラグ一覧・現在のrollout設定・最終更新日を取得
- rolloutが0%または100%のまま30日以上更新されていないフラグを抽出
- 対象フラグ名をリポジトリ内でripgrepし、参照箇所の行数をカウント
- 「放置日数 × 参照行数」でソートしたランキングをターミナルにテーブル表示
- `--repo` と `--provider` オプションだけで設定ファイル不要で動く

### なぜ雑か

対応するフラグ管理サービスはLaunchDarklyとUnseashのみで自前実装のフラグには対応しない。フラグ同士の依存関係（あるフラグがONの時だけ意味を持つ別フラグ）は検出しない。環境（dev/staging/prod）ごとの設定差分は見ず代表環境のみ参照する。実際にコードやフラグを削除する機能は作らず一覧を見せるだけに留める。

### 雑な技術スタック候補

Node.js + Commander + LaunchDarkly REST API / Unleash API + child_process経由のripgrep呼び出し + cli-table3

## 2. るすばんワンコ無駄吠え番

- カテゴリ: ハードウェア
- 対象ユーザー: 集合住宅でペットを留守番させていて近隣への吠え声トラブルを気にしている飼い主
- 一行で: マイク付きの小型デバイスを置くだけで留守中に吠え続けた時間帯をグラフとLINEで教えてくれるのだ

### 解決する痛み

管理会社や隣人から「お宅の犬、日中ずっと吠えてますよ」と苦情が来て初めて、留守中の愛犬がそんなに吠えていたことに気づく。何時頃・どれくらいの長さ吠えているか分からないと留守番トレーニングの計画も立てられない。ペットカメラを常時録画すると容量も通信量も月額料金もかさみ、結局見返さずに放置してしまう。「吠えた時間帯だけ知りたい」のに録画し続けるのは大げさすぎる。

### 1 週間で作るならこれ

- Raspberry Pi Zero 2 W + USBマイクで室内音量をリアルタイム取得
- 一定dB以上の音が5秒以上継続したら「吠え」として開始・終了時刻をログに記録
- 1日の吠え時間帯をヒートマップ風に表示するローカルWebダッシュボード
- 吠えが3分以上連続したらLINE Notify的なAPIで「長時間吠えてます」を通知
- 録音データ自体は保存せずタイムスタンプと継続時間だけを蓄積

### なぜ雑か

犬の鳴き声と来客インターホン・工事音などの判別はせず音量閾値だけで「吠え」と見なす。複数頭飼いの場合も区別せず部屋全体の音量としてまとめて扱う。Wi-Fi接続前提で外出先からのリアルタイム聞き取り機能は作らない。音声そのものは保存しないため誤検知の後から確認する手段がない。

### 雑な技術スタック候補

Raspberry Pi Zero 2 W + USBマイク + Python (sounddevice) + Flask (ローカルダッシュボード) + LINE Notify API

## 3. 面接質問かぶり防止くん

- カテゴリ: 業務ツール (Web)
- 対象ユーザー: 複数人で同じ候補者を面接する採用担当・エンジニアリングマネージャー
- 一行で: 各面接官のメモを貼るだけで候補者に同じ質問を何度もしていないか教えてくれるのだ

### 解決する痛み

一次・二次・最終と立て続けに面接すると、候補者から「それさっきも聞かれました」と言われて気まずい空気になる。面接官同士で「誰が何を聞いたか」を毎回Slackで確認し合うのは面倒で、結局「転職理由は」「強みは」といった鉄板質問を全員がそれぞれ聞いてしまい、候補者の限られた面接時間を無駄にする。事前に質問リストを共有していても当日は自由に聞いてしまうため形骸化しがちで、誰かがまとめて気づく仕組みがない。

### 1 週間で作るならこれ

- 各面接官が面接後に書いた自由テキストのメモを候補者ごとに貼り付けるフォーム
- AIでメモの中から「聞いた質問」らしき文を抽出
- 候補者単位で質問同士の意味的な類似度を比較し、重複度が高いペアをハイライト表示
- 「この質問は3人中2人が聞いています」の形で一覧化
- 次の面接官がコピペして使える「もう聞かれた質問リスト」を出力

### なぜ雑か

質問の抽出は文末が「？」で終わる文などをそれっぽく拾うだけで厳密な構文解析はしない。候補者の回答内容の重複までは見ず質問文の重複のみを対象にする。面接中のリアルタイム共有は作らず面接後の事後チェックに限定する。アカウント管理や権限分けは作らずURLを知っていれば誰でも閲覧できる前提にする。

### 雑な技術スタック候補

Next.js + OpenAI API (embeddingsで類似度判定) + Supabase (一時保存) + Vercel
