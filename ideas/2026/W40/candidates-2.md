## 1. テスト本番API誤爆検知官

- カテゴリ: CLI
- 対象ユーザー: モックを書き忘れて本番APIやDBを叩くテストに冷や汗をかいた経験があるバックエンドエンジニア
- 一行で: テスト実行のログを渡すだけで本番っぽいドメインへのHTTPリクエストが混じっていないか教えてくれるのだ

### 解決する痛み

CIでテストを流したら知らないうちに本番の決済APIや外部SaaSに本物のリクエストが飛んでいて、後から利用ログや請求で発覚して青ざめる。モックの設定漏れは目視レビューでは気づきにくく、テストがたまたま通ってしまうと誰も疑わない。とくに新人が既存のテストをコピペして書くと、環境変数の切り替え忘れでそのまま本番URLを叩くことがある。テストのレスポンスがやけにリアル、実行時間が妙に長い、といった違和感を毎回目で追うのは疲れる。

### 1 週間で作るならこれ

- pytest/jestのテスト実行時にHTTPクライアントをフックしてリクエストURLをログファイルに書き出す簡易ラッパーを用意
- ログファイルを渡すと許可リスト外のホストへのリクエストを一覧化するCLIコマンドを作成
- ホスト名に`prod`や実サービスドメインが含まれ、かつモック用ホスト（`localhost`・`.test`・`mock.`）でないものを怪しいリクエストとして検出
- 検出件数とリクエスト先ホストをテーブル表示、CIであればexit code 1で失敗させる
- 許可リストはYAMLファイルで手動管理（自動学習はしない）

### なぜ雑か

HTTPクライアントのフックはPython（requests/httpx）とJS（fetch/axios）の主要ライブラリのみ対応、その他言語は対象外。リクエストボディやヘッダーの中身は見ずURLのホスト名だけで判定する。誤検知（本当にモックサーバーなのに疑わしいホスト名）は許可リストに手で追加してもらう運用。並列実行テストのログ順序が入り乱れても気にしない。

### 雑な技術スタック候補

Python + requests-mock/responses のフック機構を参考にした簡易プロキシ + Click (CLI) + PyYAML

## 2. 会議だれてまうポイント検出くん

- カテゴリ: Web (AI ツール)
- 対象ユーザー: 定例会議の進行や資料を見直したいマネージャー・ファシリテーター
- 一行で: 会議の録音を渡すだけで参加者の発言が急に減った「だれた瞬間」をタイムスタンプで教えてくれるのだ

### 解決する痛み

自分が話しているときは気づかないが、会議の後半になるとみんな相槌だけになって実質独り言になっていることがある。「あのあたりから空気が重かった気がする」という感覚はあっても、議事録を読み返しても分からない。ファシリテーション改善のために録音を最初から最後まで聞き直す時間はない。どこで議論が停滞したかが分かれば、次回はそのトピックの説明を変えるとか時間配分を見直せる。

### 1 週間で作るならこれ

- 会議録音ファイル（mp3/m4a）をアップロードするだけのシンプルな画面
- Whisper APIで発言区間と話者交代のタイムスタンプを取得（簡易的な発話区間検出）
- 5分ごとの区間で「発言者の異なり数」と「発言の総秒数」を集計してスコア化
- スコアが直前の区間より大きく下がった箇所を「だれたポイント」として時刻付きで一覧表示
- 一覧をクリックすると該当区間の音声を直接再生できるだけ（文字起こし全文表示はしない）

### なぜ雑か

話者分離は厳密なダイアライゼーションではなく音量・無音区間からの簡易推定のみで精度は粗い。オンライン会議特有のミュート・ノイズには対応しない前提（対面またはクリアな録音のみ）。1時間を超える録音は処理時間・課金の都合で非対応。「だれた理由」の分析や改善提案はせず時刻を指し示すだけ。

### 雑な技術スタック候補

Next.js + OpenAI Whisper API + ffmpeg (音量・無音区間解析) + Vercel Blob (音声一時保存)

## 3. 寝過ごしバイブくん

- カテゴリ: モバイル (PWA)
- 対象ユーザー: 電車・バス通勤中に寝落ちして毎回乗り過ごす人
- 一行で: 降りる駅を登録するだけで近づいたらスマホが振動で叩き起こしてくれるのだ

### 解決する痛み

疲れて電車で寝落ちすると、気づいたら終点や隣町まで運ばれていて余計な時間とお金を溶かす。目覚ましアプリで時間指定しても電車の遅延や乗り換えで狂うし、音を鳴らすタイプは車内で恥ずかしくて結局切ってしまう。地図アプリを開きっぱなしにしてバッテリーを溶かすのも避けたい。GPSで位置を見て降りる駅の手前で静かに振動してくれるだけでいい。

### 1 週間で作るならこれ

- 降りる駅を地図上でタップして緯度経度を登録する画面（複数路線分を保存可能）
- PWA起動中にブラウザのGeolocation APIで位置を定期取得（バッテリー節約のため精度は粗めの間隔）
- 登録駅から半径800m圏内に入ったらVibration APIでスマホを振動させる
- 振動と同時に画面に大きく「まもなく到着」を表示（画面を見ていなくても音でも一応鳴らす）
- 到着後にワンタップで「起きた」を押すと振動が止まる

### なぜ雑か

地下鉄などGPSが入らない区間では機能しない（地上路線のみ対応が前提）。駅の座標は手入力なので路線データベースとは連携しない。バックグラウンドでの位置取得はブラウザやOSの制約でスリープすると止まることがあるが対応しない。誤差800m圏内なので隣駅と近い場合は誤発火する。

### 雑な技術スタック候補

React (Vite) + PWA (vite-plugin-pwa) + Geolocation API + Vibration API + localStorage (駅登録データ保存)
