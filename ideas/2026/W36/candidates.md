## 1. コミット詐欺検知くん

- カテゴリ: CLI
- 対象ユーザー: チームのコミット履歴を監査したいテックリード・レビュアー
- 一行で: コミットメッセージと実際のdiffの規模を突き合わせて「タイポ修正」なのに500行変えてる嘘コミットを見つけてくれるのだ

### 解決する痛み

「タイポ修正」「軽微な変更」「small fix」と書かれたコミットを開いたら実は挙動が変わる大改修だった、ということが履歴に埋もれている。レビュー時は気づいても、後から履歴を辿る人はメッセージだけを信じて読み飛ばしてしまい、バグ調査で無駄に時間を溶かす。全コミットを手作業でチェックする余裕はチームにない。メッセージの「自己申告」と実態がズレているものだけ機械的に洗い出したい。

### 1 週間で作るならこれ

- `git log --stat` で全コミットのメッセージ・変更行数・変更ファイル数を取得
- 「タイポ」「軽微」「minor」「small」「tiny」「fix typo」等のキーワード辞書でメッセージを判定
- 該当メッセージなのに変更行数50行超 or ファイル数5件超なら「ミスマッチ」判定
- ミスマッチしたコミットをハッシュ・メッセージ・行数付きでランキング表示
- `--csv` オプションでランキングをCSV出力

### なぜ雑か

キーワード辞書は日英合わせて数十語のみで意味解析はしない単純マッチ。diffの中身は読まず行数とファイル数だけで判定するので大規模フォーマット変更も誤検知する。マージコミットやリバートコミットは除外せず紛れ込む。閾値（50行/5ファイル）はハードコードで調整オプションなし。過去メッセージの言語（英語/日本語以外）は未対応。

### 雑な技術スタック候補

Node.js + simple-git + commander + chalk + csv-writer

## 2. 冷蔵庫あけっぱなし番

- カテゴリ: ガジェット
- 対象ユーザー: 一人暮らしや家族で冷蔵庫を共有していて閉め忘れが多い人
- 一行で: ドアにセンサーを貼るだけで冷蔵庫が開けっぱなしになったらブザーとLINEで教えてくれるのだ

### 解決する痛み

荷物が両手いっぱいの時に足でドアを閉めたつもりが半ドアになっていて、庫内灯がつきっぱなしのまま朝を迎える。電気代が地味にかさむし、食品が傷んでいることに気づくのは異臭がしてから。市販の冷蔵庫アラームは高額だったりデザインが無骨で置きたくない。「開いたら教えてくれるだけ」でいいのに選択肢が少ない。

### 1 週間で作るならこれ

- ドア枠にリードスイッチとマグネットを両面テープで固定して開閉を検知
- ドアが開いてから60秒経過しても閉まらなければ本体スピーカーでブザー音を鳴らす
- ドアを閉めたら即座にブザー停止
- Wi-Fi経由でLINE Notifyに「冷蔵庫が開きっぱなしです」を送信
- 開閉回数と合計開放時間をローカルWebページに簡易表示

### なぜ雑か

リードスイッチの取り付け位置がズレると誤検知するが調整UIはない。両開き・観音開きなど複数ドアの冷蔵庫は1枚だけ監視。LINE Notify以外の通知手段は未対応。USB給電前提でケーブルが冷蔵庫脇を這ったまま完成とする。ケースは作らずむき出しで両面テープ固定。

### 雑な技術スタック候補

M5StickC Plus + リードスイッチ + Arduino IDE + LINE Notify API + 内蔵スピーカー

## 3. 日報の温度差チェッカー

- カテゴリ: Web (AI ツール)
- 対象ユーザー: メンバーの日報・週報をSlackやNotionで受け取っているマネージャー・チームリード
- 一行で: 日報のテキストを貼るだけで過去の文面と比べてトーンが急に沈んだメンバーをそっと教えてくれるのだ

### 解決する痛み

日報に「特になし」しか書かなくなった、文字数が急に減った、といった変化はメンバーが限界を迎える前のサインになりうるが、忙しいマネージャーは全員分を毎日読み比べる余裕がない。1on1の頻度を上げても拾いきれない人が出てくる。誰かが本当に不調になってから気づくのでは遅く、「なんとなく変わった」を早めに機械的に検知したい。

### 1 週間で作るならこれ

- メンバー名と日報テキストを日付付きで貼り付けるだけの入力フォーム
- LLMに日報のトーン（ポジティブ/ニュートラル/ネガティブ）と文字数をスコア化させる
- 個人ごとに過去7日平均スコアと当日のスコアを比較し、急落したら一覧に表示
- 急落したメンバーには「そろそろ声をかけ時かも」バッジを表示
- メンバーごとのスコア推移を簡易折れ線グラフで表示

### なぜ雑か

感情スコアはLLMに一言判定させるだけで精度検証はしていない（誤検知前提）。日報が自由記述で短すぎる/絵文字だけだと判定精度が落ちる。Slackやメールからの自動収集はせずコピペ入力のみのMVP。過去データが3日未満のメンバーは判定対象外にする。センシティブな心理状態を扱うため運用ルールは免責表示のみで作り込まない。

### 雑な技術スタック候補

Next.js + Claude API (トーン分類) + Supabase (履歴保存) + Recharts + Vercel
