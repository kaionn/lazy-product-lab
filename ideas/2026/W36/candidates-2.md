## 1. セムバー破り検知機

- カテゴリ: CLI
- 対象ユーザー: OSSやライブラリを公開しているメンテナ・社内npmパッケージを配布しているエンジニア
- 一行で: 2つのタグ間でexportの型・シグネチャ差分を検出してpatchのつもりが実は破壊的変更というリリースを止めてくれるのだ

### 解決する痛み

パッケージのバージョンを上げるとき「今回はバグ修正だけだからpatchでいいや」と思い込んでリリースしたら、実は関数の引数を増やしていたりexportしていた型を消していたりして、利用者のビルドが一斉に壊れる。CIのテストは自分のリポジトリ内では通るので気づけない。PRレビューでも「公開APIが変わったかどうか」までは人間はいちいちチェックしない。気づくのはIssueが荒れ始めてから、という後手対応をやめたい。

### 1 週間で作るならこれ

- 指定した2つのgitタグ/コミットでそれぞれ `tsc --declaration` してビルドし型定義ファイル(.d.ts)を生成
- 生成した2つの.d.tsをASTレベルで比較し、export名・関数シグネチャ・型定義の差分を抽出
- 差分を「追加」「変更(互換性あり)」「削除・破壊的変更」の3種に分類してターミナルに一覧表示
- package.jsonのversion差分から意図したbumpの種類(major/minor/patch)を読み取り、破壊的変更があるのにpatch/minorだった場合は赤字で警告
- `--json` オプションで差分結果をCI向けに出力

### なぜ雑か

TypeScript製パッケージのみ対応でJS純正プロジェクトは対象外。ジェネリクスの複雑な型変更や条件型の意味的な破壊は検出できず、シグネチャの表面的な差分しか見ない。overload定義が多いライブラリでは誤検知が増える。npmのdist-tag運用やprivateパッケージのスコープ差異は考慮しない。

### 雑な技術スタック候補

Node.js + TypeScript Compiler API + simple-git + commander + chalk

## 2. おくすりコールリレー

- カテゴリ: Bot (LINE)
- 対象ユーザー: 離れて暮らす高齢の親の服薬確認をしたいが毎回電話するほどでもない家族
- 一行で: 親がLINEのボタンを押すだけで「薬飲んだよ」を家族に知らせて、時間までに押されなければそっと家族グループに教えてくれるのだ

### 解決する痛み

離れて暮らす親に薬を飲んだか毎回電話やLINEで確認するのは気が引けるし、親も「監視されている」ようで嫌がる。かといって全く確認しないと飲み忘れに気づけない。介護用の見守りサービスは大掛かりで契約も高額、そこまでの段階ではない家庭がほとんど。親が普段使っているLINEの中で完結する、ボタンをワンタップ押すだけの軽い仕組みが欲しい。

### 1 週間で作るならこれ

- LINE公式アカウントのリッチメニューに「朝の薬」「夜の薬」ボタンを設置
- ボタンをタップした時刻をGoogle Sheetsに記録
- 設定した服薬時刻+2時間経過してもタップがなければ家族LINEグループにだけ通知
- タップされたら記録するだけで親本人には追加のやりとりを一切求めない
- 家族側は週次の服薬タップ履歴を一覧表示するWebページを閲覧可能

### なぜ雑か

複数種類の薬・複数人分の管理は不可（親1人・朝晩2ボタン固定）。押し忘れと未服薬の区別はできない（ボタンを押しただけで実際に飲んだ保証はない）。タイムゾーンや外出時のズレは考慮しない。LINE公式アカウントの月間メッセージ数上限に達したら通知が止まる。高齢者向けの文字サイズ調整やUIの作り込みはしない。

### 雑な技術スタック候補

LINE Messaging API + LIFF + Google Apps Script + Google Sheets + GitHub Actions (定期チェック)

## 3. 見えない残業あぶり出し

- カテゴリ: 業務ツール (Web)
- 対象ユーザー: 定時後も無意識にSlackやGitHubで作業してしまうエンジニア本人・働き方を見直したいマネージャー
- 一行で: SlackとGitHubのアクティビティ時刻を突き合わせるだけで定時後にこっそり働いた時間を週次レポートにしてくれるのだ

### 解決する痛み

「残業はしていません」と申告していても、定時後にSlackで返信したりPRをマージしたりする時間が積み重なっている人は多い。本人は「ちょっと確認しただけ」のつもりでも可視化されていないので誰も気づかず、燃え尽きるまで放置される。人事の勤怠システムは自己申告ベースで実態を反映しない。かといって行動監視ツールを導入するのは大げさで社員の反発も強い。

### 1 週間で作るならこれ

- SlackのユーザートークンでAPIを叩き、本人が投稿したメッセージのタイムスタンプを取得
- GitHubのPersonal Access Tokenでコミット・PRコメントのタイムスタンプを取得
- 設定した定時（例:19時）以降のアクティビティ件数と最終アクティビティ時刻を日別に集計
- 週次で「定時後アクティビティが多かった曜日トップ3」を本人にだけメール送信
- ダッシュボードで過去4週間の定時後アクティビティ件数の推移をグラフ表示

### なぜ雑か

アクティビティの中身（重要な障害対応か雑談か）は区別せず件数だけで判定する。フレックス制や裁量労働の人には不向きな一律の「定時」設定しかできない。本人以外が勝手に他人のレポートを見られないようアクセス制御は最低限のみ。SlackとGitHub以外のツール（Notion、Jira等）は対象外。祝日・有給の除外処理はしない。

### 雑な技術スタック候補

Next.js + Slack Web API + GitHub REST API + Supabase + Resend + Recharts
