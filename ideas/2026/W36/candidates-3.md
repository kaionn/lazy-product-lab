## 1. ねこごはんチェッカー

- カテゴリ: ガジェット
- 対象ユーザー: 出社日があって留守番中の猫が心配な一人暮らしの猫飼い
- 一行で: 餌皿に置くだけで猫が餌を食べたかを重さで判定してLINEで教えてくれるのだ

### 解決する痛み

出社した日、「今日ちゃんと朝ごはん食べたかな」が気になって仕事に集中できない。自動給餌器はタイマー通りに餌を出すだけで、実際に猫が食べたかまでは教えてくれない。カメラ型の見守りは常時通信量が多いし、そもそも画面を張り付いて見る余裕がない。皿の重さが減ったかどうかさえわかれば、それで十分安心できる。

### 1 週間で作るならこれ

- ロードセル+HX711を使った重量センサーを皿の下に敷く簡易台をダンボールで自作
- ESP32が5分おきに重量を計測してWi-Fi経由でサーバーに送信
- 朝の登録時刻から一定時間（例: 3時間）重量が減らなければLINE Notifyでアラート
- 減った重量からグラム換算しておおよその食べた量を表示するだけの簡易ダッシュボード
- 皿は1枚のみ対応、多頭飼いの識別はスコープ外

### なぜ雑か

猫が皿を叩いて倒したり誤差が出ても補正しない。多頭飼いの場合は誰が食べたか区別できない。停電・Wi-Fi切断時のログ欠損は無視。皿を洗うたびにセンサーの位置がズレる問題にも対応しない。ケースは剥き出しのまま完成とする。

### 雑な技術スタック候補

ESP32 + HX711 + ロードセル + Firebase Realtime Database + LINE Notify API + HTML1枚の簡易ダッシュボード

## 2. N+1クエリ狩り

- カテゴリ: CLI
- 対象ユーザー: ORMを使うバックエンドエンジニアで本番APIが遅い原因を探れていない人
- 一行で: SQLクエリログを流し込むだけでループ内で発行された類似クエリの塊を検出してくれるのだ

### 解決する痛み

「このAPI遅いんだよな」と思いつつAPM契約の予算もなく、ログを目視で追う気力もない。ORMは便利だが気づかないうちにN+1クエリを量産しがちで、開発環境ではデータ件数が少なく症状が出ない。本番でユーザーが増えてから「あれ、遅い」と気づいたころには手遅れ気味。ログさえあれば怪しい箇所は機械的に見つけられるはず。

### 1 週間で作るならこれ

- Postgresのスロークエリログ、またはORM（Prisma等）の生クエリログをファイルで読み込む
- クエリをプレースホルダ化（`WHERE id = 1` → `WHERE id = ?`）して正規化しグループ化
- 同一正規化クエリが1秒以内に10回以上連続発行されていたらN+1候補として検出
- 検出結果を「クエリ本文・発生回数・推定合計実行時間」でランキング表示
- ランキングはターミナルへのテーブル出力のみ（HTMLレポート等は作らない）

### なぜ雑か

JOINで解決できるかの改善提案機能はなく、検出するだけ。バインド変数の型ゆれによる正規化ミスは無視し、たまに誤検出する。トランザクション境界やクエリ間の因果関係は考慮しない。対応フォーマットはPostgresのログのみで、他DBは各自変換して食わせる前提とする。

### 雑な技術スタック候補

Python + Click + 正規表現によるクエリ正規化 + rich（テーブル表示） + pytest

## 3. コントラスト比違反ハンター

- カテゴリ: Browser Extension
- 対象ユーザー: リリース前のアクセシビリティチェックを手動でやる余裕がないフロントエンドエンジニア
- 一行で: 拡張機能を開くだけでいま見ているページのWCAGコントラスト比違反を洗い出してハイライトしてくれるのだ

### 解決する痛み

アクセシビリティ対応が大事だとわかっていても、専用ツールを都度起動して細かくチェックする余裕がスプリント終盤にはない。デザイナーが選んだ薄いグレー文字が実は基準未達のまま本番に出てしまい、あとでユーザーから「読みにくい」と言われて初めて気づく。ページを開いた瞬間に「ここが危ない」とざっくりわかれば、それで十分役に立つ。

### 1 週間で作るならこれ

- 拡張機能アイコンをクリックすると現在のタブのDOMを走査
- `getComputedStyle`で文字色・背景色を取得しWCAG AAの相対輝度比を計算
- 4.5:1（通常文字）/3:1（大文字）を下回る要素に赤い枠線をオーバーレイ表示
- 違反要素の数をアイコンのバッジ数字で表示するだけの簡易サマリ
- 違反箇所をクリックするとセレクタとコントラスト比の数値だけをポップアップ表示

### なぜ雑か

背景が画像やグラデーションの要素は単色背景と誤認して計算がズレる。AAAレベルやフォントサイズごとの閾値の出し分けは考慮せず一律の基準で判定する。iframe内の要素は非対応。修正案（推奨カラーコード等）は出さず「違反している」ことだけを教える。

### 雑な技術スタック候補

Chrome拡張（Manifest V3） + Vanilla JS + Content Script + chrome.action badge API
