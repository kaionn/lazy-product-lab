## 1. 未解決スレッド見逃し番人

- カテゴリ: Bot (GitHub App)
- 対象ユーザー: GitHub上でコードレビューをしているチーム、特にレビューコメントがApprove後も放置されがちな現場
- 一行で: PRがマージされた瞬間に未解決のレビューコメントスレッドが残っていないか教えてくれるのだ

### 解決する痛み

レビュアーが「ここ直して」とコメントしても、作者が返信だけして直さずマージしてしまうことがある。GitHub上では「Resolve conversation」を押し忘れたまま、あるいは議論が終わっていないのにApproveされてマージされ、後になって「あの指摘って直したんだっけ」が誰にも分からなくなる。これは需要が確認された話ではなく仮説だが、レビュー文化のあるチームなら刺さるかもしれない、という段階のアイデアである。

### 1 週間で作るならこれ

- GitHub Appとしてインストールし、対象リポジトリのPRイベントをwebhookで監視する
- PRがmergeされた瞬間にGraphQL APIで `reviewThreads` を取得しunresolvedなスレッド数を数える（これが唯一のコアフロー）
- 1件でもあればPR自体にコメントで「未解決スレッドがN件あります」+ 各スレッドへのリンクを貼る
- 合成デモ: サンプルリポジトリで未解決コメントを残したままPRをマージし、30秒以内にbotコメントが付くところだけを見せる
- 通知先はPRコメントのみとし、Slack連携などは作らない

### なぜ雑か

「未解決」の判定はGitHubのresolved/unresolvedフラグに頼るだけで、スレッドの内容が本当に対応必須かは判定しないため誤検知が出る。直接代替としてはDanger.jsの自作ルールやrequired reviewsの運用で部分的に代替できてしまい、わざわざ導入する価値があるかは未確認。配布先もGitHub Marketplaceへの申請か社内布教が必要で、最初のユーザーをどこで見つけるかは確認課題として残る。過去にマージ済みのPRは対象にしない。

### 雑な技術スタック候補

Probot + GitHub GraphQL API + Webhook + Fly.io でホスト

## 2. 備品持ち出し放置番人

- カテゴリ: ハードウェア
- 対象ユーザー: 共有の工具・計測器・モバイルバッテリーなどをオフィスや工房でシェアしているチーム
- 一行で: タグを貼った備品が持ち出されたまま一定時間戻らないと最後に持ち出した人にLINEで教えてくれるのだ

### 解決する痛み

共有の精密ドライバーやラベルプリンターが「誰かが持ってったまま返ってこない」ため、使いたい時に毎回15分探し回ることになる。借りた人に悪気はなく単に戻すのを忘れているだけだが、今どこにあるか・誰が持っているかを知る手段がない。これも検証されていない仮説で、実際にどれだけの職場がこの痛みを強く感じているかはこれから確認する必要がある。

### 1 週間で作るならこれ

- 備品にNFCタグを貼り、持ち出し時に棚横のNFCリーダー（M5Stack等）にスマホをタップしてもらう
- タップ時に社員IDと備品名をGoogle Sheetsに記録する（タップ→記録という単一のコアフロー）
- 一定時間（例: 4時間）戻ってこない備品をcronでチェックし、持ち出した人にLINE Messaging APIで「まだ持ってますか」と送る
- 合成デモ: 備品タグをタップして持ち出し登録し、待機時間を4時間→30秒に短縮した状態でLINE通知が届くところを見せる
- 棚に戻す時のタップ操作は善意に依存し、強制的な検知はしない

### なぜ雑か

タップを忘れたら記録自体が始まらず検知漏れが前提になる。直接代替としては貼り紙や付箋で「借りたら書く」ルールを運用するだけの職場も多く、ハードウェア導入のコストに見合うかは未検証。配布先も社内ツールとしてどのチームに持ち込むかが曖昧で、最初に使ってくれる現場をどう見つけるかは確認課題として残る。複数拠点対応やRFIDゲート化による完全自動検知はしない。

### 雑な技術スタック候補

M5Stack + NFCタグ + Google Apps Script（Sheets連携） + LINE Messaging API

## 3. お薬補充忘れ番人

- カテゴリ: モバイル (PWA)
- 対象ユーザー: 持病で毎日薬を飲んでいて、通院して処方箋をもらわないと薬局で受け取れない人
- 一行で: 残りの薬の数を数えるだけで切れる前に通院すべき日をスマホが教えてくれるのだ

### 解決する痛み

毎日飲む薬の残数を数えずに使い続け、ある朝「あと1錠しかない」と気づいて慌てて病院に駆け込むことがある。予約や診察待ちを考えると切れる3〜5日前には受診しておきたいが、日々の忙しさでそれを忘れる。飲み忘れ防止ではなく「補充のタイミング」に特化した痛みで、実際にどれだけの人がここで困っているかは未確認の仮説にすぎない。

### 1 週間で作るならこれ

- 薬の名前・1日の服用回数・現在の残数を入力するだけの登録画面（単一のコアフロー）
- ホーム画面で「今日飲んだ」をワンタップすると残数が自動で1減る
- 残数÷1日の服用量で「あと何日で切れるか」を計算し、画面上部に常時表示する
- 切れる5日前になったらプッシュ通知で「そろそろ病院へ」と知らせる
- 合成デモ: 残数を5に設定して1日分ずつ消費し、閾値を割った瞬間に通知が出る様子をタイマー短縮で30秒以内に再現して見せる

### なぜ雑か

頓服や用量が不規則な薬には対応しない。入力を忘れると残数がズレて通知のタイミングも狂うが、補正機能は作らない。直接代替としてはカレンダーへの通院日リマインドや薬局の電子お薬手帳アプリの一部機能と重複する可能性があり、差別化が弱いかもしれない。配布先もApp Store審査や医療関連アプリとしての扱いが曖昧で、個人開発のPWAとしてどこまでリーチできるかは確認課題として残る。家族との共有や複数人管理はしない。

### 雑な技術スタック候補

React + Vite (PWA) + IndexedDB（ローカル保存） + Web Push API
