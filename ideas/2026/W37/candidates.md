## 1. API公称通り検査官

- カテゴリ: CLI
- 対象ユーザー: OpenAPI/GraphQLスキーマを書いてはいるが実装とズレがちなバックエンドエンジニア
- 一行で: スキーマファイルと実際のAPIレスポンスを突き合わせるだけで「ドキュメントに無いフィールド」「型が違うフィールド」を洗い出してくれるのだ

### 解決する痛み

OpenAPI定義はあるものの、実装側が先に変わってドキュメントが追いつかない状態が常態化している。フロントエンドの担当者が「スキーマ通りに書いたのにnullが来た」「配列だと思ったらオブジェクトだった」とハマるたびに、結局Slackで「実際のレスポンス貼って」からのすり合わせが発生する。CIでのcontractテストを整備する余裕はないが、せめて手元で「今どれだけズレてるか」を秒で知りたい。

### 1 週間で作るならこれ

- OpenAPIのYAML/JSONファイルと、対象エンドポイントへの実際のリクエスト（curlコマンド相当）をコマンドライン引数で受け取る
- レスポンスJSONをスキーマ定義と再帰的に突き合わせて「未定義フィールド」「型不一致」「必須なのに欠落」の3種類だけ検出
- 結果を赤黄でハイライトしたテキスト表としてターミナルに出力
- エンドポイントを複数まとめて指定できるように設定ファイル（YAML）を1個だけ読めるようにする
- 差分ゼロなら exit code 0、差分ありなら 1 を返してCIに組み込めるようにする

### なぜ雑か

GraphQLは対応せずOpenAPI（JSON Schema形式）のみ対応。認証が必要なAPIはヘッダーを引数でベタ書きする前提でOAuthフローは実装しない。ネストが5階層を超える巨大スキーマは検証を諦めてスキップ扱いにする。レスポンスの配列要素は先頭1件だけ検証して残りは見ない。

### 雑な技術スタック候補

Node.js + Commander.js + ajv (JSON Schema検証) + chalk + js-yaml

## 2. 宅配ボックス満杯番人

- カテゴリ: ガジェット
- 対象ユーザー: 在宅勤務中で宅配ボックスが荷物でいっぱいになりがちな集合住宅住まいの人
- 一行で: 宅配ボックスに距離センサーを貼るだけで満杯になった瞬間LINEで教えてくれるのだ

### 解決する痛み

在宅ワーク中にネット注文が重なると、宅配ボックスがいつの間にか満杯になり、次の配達員が「入らないので持ち帰り」にしてしまう。毎回ボックスを覗きに行くのは面倒だし、忘れて再配達依頼を出す羽目になる。荷物が届いたことより「ボックスの残り容量」を知りたいのに、既存の宅配通知サービスはそこまで教えてくれない。

### 1 週間で作るならこれ

- ESP32 + 超音波距離センサーをボックスの蓋裏に両面テープで固定
- 5分おきに蓋から底までの距離を測定してボックス内の荷物の高さを推定
- 満杯しきい値（設定した高さ以下）を下回ったらLINE Notify的なWebhookで「そろそろ満杯です」と通知
- 満杯解消（荷物が取り出された）も検知して「空きました」を通知
- Wi-Fi経由でESP32上のWebページから閾値だけ調整できるようにする

### なぜ雑か

ボックスの形状ごとのキャリブレーションは手動調整任せで自動化しない。複数口の宅配ボックス（多段式）は1段しか計測しない。電源はモバイルバッテリー直結で電池残量監視は作らない。誤検知（人の手が一瞬入っただけ）を弾くフィルタは3回連続検知のみの単純ロジックで済ませる。

### 雑な技術スタック候補

ESP32 + HC-SR04超音波センサー + Arduino IDE + LINE Notify API + 単三電池パック

## 3. 引き継ぎ漏れ健診

- カテゴリ: 業務ツール (Web)
- 対象ユーザー: チームメンバーの退職・異動の引き継ぎを受け取る側のマネージャーやテックリード
- 一行で: 引き継ぎ資料のテキストを貼るだけで定番チェック項目と照らして抜けている項目を教えてくれるのだ

### 解決する痛み

退職や異動の引き継ぎは本人任せになりがちで、「本番DBのアクセス権限は？」「定期実行しているcronの一覧は？」「外部ベンダーとの連絡窓口は？」といった定番項目が抜けたまま引き継ぎが完了扱いになる。抜けに気づくのはたいてい本人が去った後で、慌てて周りに聞き回ることになる。チェックリストをExcelで作っても毎回更新されず形骸化する。

### 1 週間で作るならこれ

- 引き継ぎ資料のテキスト（Markdownやドキュメントのコピペ）を貼り付けるテキストエリア
- あらかじめ用意した定番チェック項目リスト（権限・cron・外部連絡先・進行中タスク・パスワード保管場所など20項目）とAIで照合
- 資料内に言及がない項目だけを「未記載の可能性あり」としてリストアップ
- 未記載項目をチェックボックス付きでコピーできる「確認用メッセージ」として出力
- チェック項目リスト自体は管理画面不要でJSONファイルを直接編集する運用にする

### なぜ雑か

AIによる「言及の有無」判定は誤検知・見逃しが普通にある前提で、あくまで叩き台の位置づけとする。チェック項目のカスタマイズはJSON直編集のみでUIは作らない。資料のフォーマット（PDF・Notion等）は問わずテキストのコピペのみ対応。過去の引き継ぎ履歴の保存・検索機能は持たせない。

### 雑な技術スタック候補

Next.js + OpenAI API (構造化出力) + Vercel + ローカルJSONファイル（DBなし）
