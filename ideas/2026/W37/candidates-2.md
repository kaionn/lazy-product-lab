## 1. Dockerレイヤー無駄遣い検査官

- カテゴリ: CLI
- 対象ユーザー: Dockerイメージが肥大化して困っているバックエンドエンジニア・インフラ担当
- 一行で: イメージ名を渡すだけでどのレイヤーが容量を無駄にしているか一覧にしてくれるのだ

### 解決する痛み

`docker build` が終わるたびにイメージサイズがじわじわ増えているが、`docker history` の出力は読みにくくてどのレイヤーが原因か特定できない。「たぶん apt install のキャッシュだろう」と推測でDockerfileをいじってはビルドし直す無駄なサイクルを繰り返している。特に、複数のレイヤーで同じ node_modules や apt キャッシュファイルが重複して焼き込まれていることに誰も気づかない。イメージを軽量化したいのに、どこを削れば効果があるのか可視化する手段がない。

### 1 週間で作るならこれ

- `docker save` でイメージをtarとして書き出し、レイヤーごとのdiffを展開するCLI
- 各レイヤーの追加サイズを計算してランキング表示
- 各レイヤー内でサイズが大きいファイル上位10件をリスト表示
- ファイルのSHA256ハッシュを比較して複数レイヤーに重複して存在するファイルを「無駄な重複」として警告
- 結果をターミナルの簡易テーブルとMarkdownレポートの両方で出力

### なぜ雑か

マルチアーキテクチャイメージ（arm64/amd64混在）は非対応で単一プラットフォームのみ。重複検出は完全一致ハッシュのみで、近似重複（バージョン違いの似たファイル）は検出しない。過去ビルドとの履歴比較はせず単発の診断のみ。CI連携やDockerfileの自動修正提案は作らず「どのレイヤーが悪いか」を教えるだけに留める。

### 雑な技術スタック候補

Node.js CLI + docker save (tar展開) + tar-stream + crypto (sha256) + cli-table3

## 2. 見積もり実績乖離ダッシュボード

- カテゴリ: SaaS
- 対象ユーザー: スプリントの見積もり精度を改善したいエンジニアリングマネージャー・PM
- 一行で: タスクの見積もり時間と実績時間のCSVを貼るだけで乖離の大きいタスクをランキング表示してくれるのだ

### 解決する痛み

スプリント計画で「このタスクは3時間」と見積もっても、実際どれだけかかったかを振り返る文化がなく、次の見積もりも同じ精度で外れ続ける。JiraやToggl上にデータは残っているが、両方を突き合わせて「どのタイプのタスクをいつも過小評価しているか」を分析するのは面倒で誰もやらない。レトロで「見積もり精度を上げよう」と毎回言うだけで具体策が出てこない。

### 1 週間で作るならこれ

- タスク名・見積時間・実績時間・担当者・タグの列を持つCSVをアップロードするだけの画面
- 各タスクの乖離率（実績÷見積）を計算して乖離が大きい順にランキング表示
- 見積 vs 実績の棒グラフを一覧表示
- 担当者別・タグ別に集計して「バックエンドタスクはいつも1.5倍かかる」等の傾向を表示
- 集計結果をMarkdownでエクスポートしてレトロにそのまま貼れるようにする

### なぜ雑か

Jira/Toggl等とのAPI直接連携はせずCSVアップロードのみ（毎回手動エクスポートが必要）。スプリントをまたいだ履歴トレンドの保存はせず、アップロードのたびに単発集計するだけ。乖離の原因分析（AIによる考察等）は行わない。バックエンドはなくブラウザのlocalStorageにのみ保存するため、チーム間でのデータ共有はできない。

### 雑な技術スタック候補

React (Vite) + PapaParse (CSV解析) + Chart.js + localStorage + Vercel静的ホスティング

## 3. しゃべってるのにミュートやんけ検知

- カテゴリ: デスクトップアプリ
- 対象ユーザー: オンライン会議でミュートし忘れに気づかず喋り続けてしまうリモートワーカー
- 一行で: 会議モードをONにするだけで喋っているのにマイクレベルが上がっていないと画面をピカッと光らせて教えてくれるのだ

### 解決する痛み

Zoomで熱心に説明していたら「すみません、ミュートになってます」と言われて気まずい思いをする。逆にミュート解除を忘れて独り言のつもりで愚痴を言ってしまう事故もある。会議アプリごとに小さいミュートアイコンを毎回目視確認するのは負担で、話し始める前にいちいち確認する習慣も定着しない。物理ランプを机に置く方法もあるが、そもそも自分が今喋っているのに音が拾われていないことに気づく仕組みが欲しい。

### 1 週間で作るならこれ

- メニューバーに常駐し「会議モード」をワンクリックでON/OFFする常駐アプリ
- ONの間、OSのマイク入力レベルを継続的にサンプリング
- 入力音量が一定時間（1秒程度）閾値を超えたら、画面の縁を赤くパルス点灯させて「マイク確認して」と通知
- 感度（閾値）を1本のスライダーで調整できる設定画面
- 会議終了後は手動でOFFに戻すだけ（自動検知なし）

### なぜ雑か

会議アプリ側の実際のミュート状態はAPIで取得できないため、マイク音量だけを見て「喋ってるかも」と推測する雑判定（隣の人の声や物音でも誤検知する）。会議の開始・終了を自動検知せず、毎回手動でトグルする必要がある。対応OSはmacOSのみでWindows/Linuxは対象外。音声の内容や話者識別は一切行わない。

### 雑な技術スタック候補

Electron (menubar) + node-audiorecorder / naudiodon (マイク入力取得) + BrowserWindow透過オーバーレイ
