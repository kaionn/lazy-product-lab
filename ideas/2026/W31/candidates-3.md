## 1. PR放置レーダー

- カテゴリ: Bot (GitHub App)
- 対象ユーザー: レビュー待ちPRが埋もれがちな少人数チームのテックリード・EM
- 一行で: N日以上放置されたPRを毎朝Slackに晒してレビューを催促してくれるのだ

### 解決する痛み

レビュー依頼を出したPRが「あとで見る」のまま3日も5日も放置され、気づけばマージ漏れでリリースに間に合わない。GitHubのPR一覧を毎朝手動でチェックするのは面倒だし、催促のDMを送るのも気が引ける。レビュアーは通知が埋もれて悪気なく忘れているだけなのに、放置は放置として積み上がっていく。「誰が」「どれくらい」放置しているかが一目でわかれば、催促の心理的ハードルが下がる。

### 1 週間で作るならこれ

- GitHub Appとしてインストール、対象リポジトリのopen PR一覧をREST APIで毎朝取得
- 最終アクティビティ（コメント・レビュー・push）からの経過日数を計算
- 経過日数の閾値（デフォルト3日）を超えたPRだけを抽出
- レビュアー名・PRタイトル・経過日数を1メッセージにまとめてSlack Webhookに投稿
- 閾値はリポジトリごとに`.pr-radar.yml`で1個だけ設定可能

### なぜ雑か

複数レビュアーがいる場合の担当者の按分は考えない（全員に等しく晒す）。ドラフトPRやWIPラベルの除外設定なし。土日を挟んだ経過日数もそのままカウントする。Slack以外の通知先には対応しない。同じPRを毎朝律儀に再通知し続ける（既読管理なし）。

### 雑な技術スタック候補

Probot + GitHub REST API + Slack Incoming Webhook + Vercel Cron (毎朝実行) + js-yaml

## 2. ポストくん

- カテゴリ: ハードウェア
- 対象ユーザー: 郵便受けを何度も見に行ってしまう在宅ワーカー・宅配便を待つ人
- 一行で: 郵便受けに振動センサーを貼るだけで投函があった瞬間LINEで教えてくれるのだ

### 解決する痛み

在宅勤務中、大事な書類や荷物を待っていると「もう届いたかな」と何度も郵便受けまで見に行ってしまい、集中が途切れる。宅配便の不在票は玄関を離れている間に来ることも多く、気づいたときには再配達の手間が発生している。郵便受けの蓋が開閉した瞬間だけ検知できれば、見に行く回数はゼロになる。

### 1 週間で作るならこれ

- ESP32 + 振動センサー（SW-420）を郵便受けの蓋裏に両面テープで固定
- 振動を検知したらWi-Fi経由でLINE Notify APIにメッセージ送信
- 誤検知を減らすため5分以内の連続検知はまとめて1通知に集約
- 単三電池3本で駆動、電池残量が低下したら通知に「電池交換」の一言を添える
- 設定はコード内の定数を書き換えて再書き込みするだけ（アプリなし）

### なぜ雑か

振動と投函を確実に区別できない（宅配業者が郵便受けを蹴ってもLINEが飛ぶ）。防水ケースなし、屋根付き郵便受け専用。複数世帯共有ポストへの対応なし。電池寿命の計測はしておらず「多分1ヶ月持つだろう」で終わらせる。LINE Notify以外の通知先は作らない。

### 雑な技術スタック候補

Arduino IDE + ESP32 + SW-420振動センサー + LINE Notify API + 単三電池ボックス

## 3. えーとカウンター

- カテゴリ: Web (AI ツール)
- 対象ユーザー: 社内プレゼンや登壇練習をしている口癖が気になるビジネスパーソン
- 一行で: プレゼン練習を録音するだけで「えーと」「あの」の回数を数えて教えてくれるのだ

### 解決する痛み

プレゼンや登壇の練習を録音してみても、後で聞き返すのが面倒でそのまま放置してしまう。本番で「えーと」「あのー」を連発していることに自分では気づきにくく、指摘してくれる人も周りにいない。フィラーワードの多さは自覚さえできれば意識的に減らせるのに、その自覚を得る手段がない。

### 1 週間で作るならこれ

- ブラウザでマイク録音を開始・停止するだけのシンプルな画面
- 録音終了後にWhisper APIへ送信して文字起こしとタイムスタンプを取得
- 「えーと」「あの」「まあ」など日本語フィラーワード辞書（10語固定）でカウント
- 発話時間とフィラー回数から「1分あたりの回数」をスコアとして表示
- 文字起こし全文にフィラー箇所をハイライトして該当秒数にジャンプ表示

### なぜ雑か

フィラーワード辞書は固定10語でカスタマイズ不可、方言や独自の口癖は拾えない。話者分離なし（1人分の録音前提）。録音は5分までしか対応しない（Whisperの処理時間とコストの都合）。過去の録音履歴を並べたトレンドグラフは作らない（1回ずつの使い切り）。ノイズが多い環境での認識精度は保証しない。

### 雑な技術スタック候補

Next.js + MediaRecorder API + OpenAI Whisper API + 正規表現によるフィラーワードカウント + Vercel
