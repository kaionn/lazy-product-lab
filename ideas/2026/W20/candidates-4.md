## 1. DailyRetro

- カテゴリ: SaaS
- 対象ユーザー: 月次振り返りをやりたいが日次記録が続かない個人開発者・フリーランサー
- 一行で: LINE通知に3行返すだけで月報が自動生成されるのだ

### 解決する痛み
「今月何やったっけ」と毎月末に頭を抱える。Notionで日報テンプレートを作るが3日で途絶える。TimelineやTogglは記録の粒度が細かすぎて「成果」ではなく「作業」しか残らない。振り返りたいのに材料がない、だから振り返れない、だから成長実感がない、という負のサイクル。

### 1 週間で作るならこれ
- LINE Messaging API で毎晩 22:00 に「今日の3行日報は?」プッシュ通知
- LINE返信テキストをそのまま日付ラベル付きでDBに保存（フォーマット自由）
- 毎月1日に前月分を束ねてMarkdown月報を自動生成（日付順リスト形式）
- 月報をLINEで送信 + メールにも転送
- Webダッシュボード (Flask) で過去の日報を検索・一覧閲覧

### なぜ雑か
LINE返信以外の入力手段なし。日報フォーマット自由すぎて月報の質は自分次第。22:00 固定でリマインダー時刻変更不可（MVP版は）。月報の整形はLLMで要約せず生テキスト結合のみ。

### 雑な技術スタック候補
Python + Flask + LINE Messaging API + SQLite + Railway 無料枠でホスト、APScheduler でcron代替

## 2. ミドリメーター

- カテゴリ: ハードウェア
- 対象ユーザー: 植物を枯らし続けている一人暮らし社会人・在宅ワーカー
- 一行で: 土の乾燥をOLEDとブザーでリアルに知らせるコスト800円デバイス

### 解決する痛み
観葉植物を2週間で枯らして「植物は自分には無理」と諦めるサイクルを3回繰り返している。スマートプランターは5000円以上で高い。「なんとなく毎日水あげ」は過湿で根腐れさせる。乾燥しているかどうかを手が土で汚れずに知りたい。

### 1 週間で作るならこれ
- Capacitive土壌水分センサー（¥200）+ D1 Mini ESP8266（¥300）+ 0.96" OLED（¥300）で配線
- センサー値を 0-100% の湿度として OLED に大きく表示（アイコン付き）
- 3段階アラート: 十分(緑LED)・注意(黄LED点滅)・カラカラ(赤LED+ブザー3秒毎)
- `http://midori.local/` でブラウザから現在値と過去24hグラフを確認
- Web UIのスライダーで乾燥しきい値を植物種別に合わせて調整

### なぜ雑か
センサーは安物なので精度±20%は誤差内。1台で1鉢のみ対応（複数植物は複数台買ってほしいのだ）。防水処理なしなので鉢の縁に刺して本体は外側に置くこと。電源はUSBのみ。

### 雑な技術スタック候補
Arduino C + ESP8266WebServer + Adafruit_SSD1306 + Chart.js (ブラウザ側) + LittleFS でデータ保存

## 3. PR BGM Action

- カテゴリ: その他
- 対象ユーザー: PRレビューを義務感から楽しいイベントに変えたいエンジニアチーム
- 一行で: PRの規模と内容に応じてBGMタグを自動でコメントするのだ

### 解決する痛み
PRレビューが「義務消化」になっていてモチベーションが上がらない。デカいPRを開くたびにため息が出る。絵文字でリアクションするだけでは空虚。「このPRにはこの曲が合う」というジョークが一周回って文化になれば、レビュー依頼を出す側も気軽になる。

### 1 週間で作るならこれ
- GitHub Actions で PR open/update をトリガに起動
- 変更行数・変更ファイル拡張子・PRタイトルのキーワードを分析
- ルールに基づいてBGMカテゴリを判定（例: 1000行超→Epic Orchestra, バグ修正→Lo-fi, テスト追加→Study Music）
- 判定したカテゴリ名 + YouTube検索リンク + 一言コメントをPRボディにコメントとして投稿
- `.github/pr-bgm.yml` でキーワード→BGMカテゴリのマッピングをチームがカスタマイズ可能

### なぜ雑か
LLMは使わず固定ルールのみ（条件分岐がすべて）。同一PRへの重複コメント防止なし（更新のたびにコメントが増える）。YouTubeリンクはキーワード検索URLなので何が出るかは不明。PRタイトルが英語前提。

### 雑な技術スタック候補
GitHub Actions (YAML) + Python スクリプト + PyGithub + GitHub Secrets でトークン管理
