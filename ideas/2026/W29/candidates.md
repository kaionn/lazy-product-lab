## 1. PagePal

- カテゴリ: Bot (Discord)
- 対象ユーザー: Discord 上で非同期読書会をやりたいグループ・社内 TechBook Club のメンバー
- 一行で: ページメモを Discord に投げるだけで読書会が回る

### 解決する痛み

オンライン読書会で感想を共有しようとすると、Notion ドキュメント・Slack スレッド・Google Doc など場所が毎回バラバラになる。全員がリアルタイムで VC に集まれないので非同期でやりたいが、「今週ここまで読んだ人が/digest と打てば全員のメモが見られる」というシンプルな仕組みがない。Discord のスレッドに書き込んでも後からページ番号で絞り込めず混沌とする。

### 1 週間で作るならこれ

- `/read-start "The Pragmatic Programmer"` でサーバー内の読書セッション開始
- `/note 42 "DRY 原則の説明が具体的で分かりやすい"` でページ番号付きメモを記録
- `/digest` で参加者全員のメモをページ順に整形してチャンネルに投稿
- `/status` で各メンバーの最終記録ページを一覧表示（誰が一番先を読んでいるか一目瞭然）
- 毎週日曜 09:00 に自動で週次ダイジェストを投稿する cron

### なぜ雑か

複数本の同時進行なし（サーバー 1 冊縛り）。Kindle の位置番号には非対応でページ番号のみ。ネタバレ隠し機能なし。サーバーをまたいだ統計や個人プロフィールなし。DB は SQLite on Fly.io の 256MB 無料枠で、大規模サーバーでは詰まる可能性がある。

### 雑な技術スタック候補

discord.py + SQLite + Fly.io 無料枠 + schedule ライブラリで cron 代替

## 2. SilentTODO

- カテゴリ: VS Code Extension
- 対象ユーザー: レガシーコードを引き継いだ開発者・TODO コメントが 200 個溜まっているプロジェクトの担当者
- 一行で: 全 TODO を作者・放置年数付きでサイドバーに叩き出す

### 解決する痛み

`// TODO: あとで直す` が誰の・いつのコメントか分からず年単位で放置される。VS Code の検索パネルでは「一覧をキープしながら各ファイルに飛ぶ」ができないし、飛ぶたびに再検索が必要になる。200 個ある TODO のうちどれが致命的でどれが無害な愚痴なのか、齢（何日前に書いたか）を見ると一目で分かるのに、標準機能にはない。

### 1 週間で作るならこれ

- ワークスペース全体から `TODO` / `FIXME` / `HACK` / `XXX` を一括スキャン
- サイドバーのツリービューにファイル別グルーピングで表示
- `git blame` を裏で呼び出して作成者名・コミット日・経過日数を各行に表示
- アイテムをクリックするとエディタの該当行にジャンプ
- 「スヌーズ 7 日」でリストから一時非表示にし雑音を減らす

### なぜ雑か

`git blame` はファイル保存ごとに自動更新されず、手動リフレッシュ必須。マルチルートワークスペースの 2 つ目以降は無視。`// todo` (コロンなし・小文字) などの非標準フォーマットは検出できない。TODO の優先度タグ付けやアサイン機能なし。blame に失敗した場合（git 管理外ファイル等）は作者欄が「不明」になるだけでエラー表示なし。

### 雑な技術スタック候補

VS Code Extension API + TypeScript + child_process で `git blame` 呼び出し + `vscode.workspace.findFiles` + WebviewPanel なし（TreeDataProvider のみで完結）

## 3. httpsnap

- カテゴリ: ライブラリ (Python)
- 対象ユーザー: 外部 API を叩くコードのテストを書きたい Python 開発者
- 一行で: デコレータ 1 行で HTTP モックの記録・再生が全自動

### 解決する痛み

`requests-mock` や `responses` でモックを書こうとすると、テストごとにレスポンス JSON を手書きして管理しなければならず、API 仕様が変わるたびに手直しが辛い。`VCR.py` は設定が複雑で cassette パスを毎回指定しなければならない。「初回だけ本物の API を叩いて、あとはスナップショットで再生」という動作をデコレータ 1 つで完結させたい。

### 1 週間で作るならこれ

- `@httpsnap.record` をテスト関数に付けるだけで動作（設定ファイル不要）
- 初回実行時に `.snap/<test_name>.json` に全 HTTP レスポンスを自動保存
- 2 回目以降はスナップショットを自動再生、ネットワーク不要
- `httpsnap update` コマンドで全スナップショットを一括再録
- `requests` と `httpx` の両方のセッションをインターセプト対応

### なぜ雑か

gRPC / WebSocket 未対応。レスポンスに含まれるタイムスタンプやランダム ID はスナップごとに変わるため、完全一致を保証しない（ヘッダとボディを別々に保存するだけ）。認証ヘッダの自動マスクなし（手動でフィルタ関数を渡す必要あり）。pytest 専用で unittest 単体の動作は未確認。非同期 (`asyncio`) テストは実験的サポートのみ。

### 雑な技術スタック候補

Python 3.10+ + pytest プラグイン + `responses` ライブラリでインターセプト + JSON スナップショット保存、PyPI に `pip install httpsnap` で配布
