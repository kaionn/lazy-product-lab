## 1. 秘密コピペ検問所

- カテゴリ: Browser Extension
- 対象ユーザー: SlackやGitHub、X（Twitter）にAPIキーやトークンをうっかり貼り付けて公開してしまう開発者
- 一行で: 投稿欄に貼り付けた文字列がAPIキーっぽいと投稿前にポップアップで止めてくれるのだ

### 解決する痛み

開発中はターミナルやconfig、.envファイルからコピーした文字列をそのままSlackメッセージやGitHub Issue、Xの下書きに貼ってしまうことがある。特に急いでいる時や複数タブを行き来している時は貼った直後に気づかず送信ボタンまで押してしまい、公開後に慌てて削除してキーを失効させる羽目になる。gitleaksのようなツールはリポジトリ内は守ってくれるが、SlackやWebフォームへの貼り付けまでは監視してくれない。投稿ボタンを押す直前の「最後の砦」が欲しい。

### 1 週間で作るならこれ

- Chrome拡張でテキストエリア/inputへのpasteイベントを監視
- AWSキー・Slackトークン・GitHub PAT等の正規表現パターン十数種でマッチ判定
- マッチした場合、該当欄の上に赤い警告バナーを表示して3秒間だけ注意を引く
- 警告を無視して送信ボタンを押しても止めない（あくまで注意喚起のみ）
- 監視対象ドメインはオプション画面でホワイトリスト管理（デフォルトはSlack/GitHub/X）

### なぜ雑か

正規表現ベースなので誤検知（テスト用ダミーキー等）も拾う。エントロピー計算による精度向上はしない。送信自体をブロックする機能はなく警告のみで、強制ブロックは実装しない。ChromeのみでFirefox/Safari拡張には対応しない。貼り付け以外（手打ちでの入力）は監視しない。

### 雑な技術スタック候補

Chrome Extension (Manifest V3) + content script + 正規表現パターン集（gitleaksルール流用）

## 2. 会議アジェンダ催促人

- カテゴリ: Web (SaaS)
- 対象ユーザー: 社内会議を頻繁に主催するがアジェンダを書き忘れがちなマネージャー・PM
- 一行で: 説明欄が空のままの会議が近づくと主催者にだけそっとアジェンダ催促メールを送ってくれるのだ

### 解決する痛み

会議の予定は入れたもののGoogleカレンダーの説明欄を空のまま放置し、開始直前になって「何を話すんだっけ」と参加者全員が手探りで始まる会議は無駄が多い。主催者自身も直前まで気づかず、結局その場で議題を思い出しながら進行するので時間だけが過ぎていく。Slackで都度リマインドを頼むのも角が立つし、自分で毎回カレンダーを見返して確認するのも面倒。開始30分前に「まだ空欄です」と本人にだけそっと教えてくれれば十分。

### 1 週間で作るならこれ

- Google Calendar APIでOAuth連携し、対象カレンダーの今後の予定を15分おきにポーリング
- 開始30分前かつ説明欄が20文字未満の予定を「アジェンダ未記入」と判定
- 主催者のメールアドレスへResendで「◯◯の会議、アジェンダまだです」を1通だけ送信（スヌーズなし）
- 送信済みフラグをDBに記録し同じ予定への二重送信を防止
- 対象カレンダーはユーザーごとに1つだけ登録可能

### なぜ雑か

Google Calendar限定でOutlook/Notion等には対応しない。アジェンダの「質」は判定せず文字数だけで空欄扱いを回避できてしまう。参加者への通知は一切しない（主催者のみ）。定例会議など毎回アジェンダが同じ場合の除外設定はない。催促は1回のみで直前になっても送り直さない。

### 雑な技術スタック候補

Next.js + Google Calendar API + Supabase (DB + pg_cron) + Resend + Vercel

## 3. 傘持ったっけ番

- カテゴリ: モバイル (PWA)
- 対象ユーザー: 天気予報を見ずに家を出て、雨に降られたり傘を職場に置き忘れたりを繰り返す人
- 一行で: 雨予報の日だけ出発前と退勤前にスマホが「傘は?」と聞いてくれるのだ

### 解決する痛み

天気予報をチェックする習慣がなく、家を出てから雨に気づいて濡れて出勤する、あるいは傘を持って出たのに退勤時にはすっかり忘れて置いてきてしまう、という往復どちらかで必ず失敗する。天気アプリの通知は毎朝一律に来るだけで「今日は傘が要る」という行動を促すところまではやってくれない。傘を持ったかどうかを自分でメモするのも続かない。

### 1 週間で作るならこれ

- 起床時刻を1回設定し、その30分前に降水確率（Open-Meteo API）が50%以上なら「傘を持った?」のプッシュ通知（はい/まだの2択）
- 「はい」を押すとその日1日分の「傘所持フラグ」を端末内に保存
- 勤務先の位置情報を1箇所ジオフェンス登録し、退勤時にそのエリアを出る瞬間、当日のフラグが立っていれば「傘忘れてない?」を再通知
- 通知はプッシュのみでアプリを開かなくても完結
- 天気判定は毎日1回・1地点（自宅の緯度経度固定）のみ

### なぜ雑か

天気予報がハズレて突然の通り雨には対応できない。傘所持フラグは自己申告制で本当に持ったかは検証しない。ジオフェンスの半径や職場登録は1箇所のみで複数の外出先には対応しない。Android/iOSのバックグラウンド位置情報の精度差は無視する。家族分の共有機能はない。

### 雑な技術スタック候補

Expo (React Native, PWA配信) + Open-Meteo API + expo-location (ジオフェンス) + expo-notifications
