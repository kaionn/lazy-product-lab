## 1. LinkCoroner

- カテゴリ: SaaS
- 対象ユーザー: 過去記事に大量のリンクを貼っているブログ書き・コンテンツライター
- 一行で: 過去記事のリンク切れを週1で自動監視して通知

### 解決する痛み

数年前に書いたブログ記事に貼った外部リンクが、気づかぬうちに 404 や別サービスの広告ページになっている。Linktree や bit.ly などの短縮サービスが廃止されたリンクも放置しがち。SEO 的にもリンク切れは悪影響なのに、全記事を手動チェックする時間は永遠にとれない。「いつかやろう」のまま積み上がり続ける問題。

### 1 週間で作るならこれ

- サイトマップ URL か RSS フィード URL を登録するだけでセットアップ完了
- 全記事のリンクを週1クロールして HTTP ステータスをチェック
- ダッシュボードで死んだリンクを「記事別」「ドメイン別」に一覧表示
- 新たなリンク切れが出たらメールで通知
- 「よく死ぬドメイン TOP 10」ランキング表示で傾向把握

### なぜ雑か

クローリングは robots.txt を無視。認証が必要なページや JavaScript 動的生成のリンクは取得できない。チェック頻度は週1固定で変更不可。月 500 リンクまでの無料枠のみ（それ以上は未実装で黙って止まる）。

### 雑な技術スタック候補

Python + FastAPI + Celery + Redis + SQLite、Render 無料枠ホスト + SendGrid 無料枠でメール通知

## 2. BarShelf

- カテゴリ: モバイル
- 対象ユーザー: 本・CD・ゲームを大量に持つコレクター・積読常習犯
- 一行で: バーコードを撮るだけで棚の中身をデジタル管理

### 解決する痛み

Amazon で本を買おうとしたら既に持っていた、という体験が繰り返される。「あの本どこに置いたっけ」「友達に貸したまま 2 年経った」も頻発する。本棚の中身をリスト化しようとしても手打ちが面倒すぎて挫折するし、Notion テンプレートを作っても入力が続かない。バーコードを「パシャ」の一動作だけで登録できれば習慣になる。

### 1 週間で作るならこれ

- カメラで ISBN バーコードをスキャン → Open Library API で書影・タイトル・著者・出版年を自動取得
- ローカル SQLite に保存（クラウド不要）
- 検索・一覧表示・ジャンル絞り込み
- 「貸し出し中」フラグ + 貸した相手メモ欄
- 重複スキャン時に「これ持ってるよ」アラートをトースト表示

### なぜ雑か

ISBN のないもの（古い本・雑誌・自炊データ）はスキャン不可。クラウド同期なし・端末ローカルのみ。複数棚の物理場所管理なし。Open Library API が知らない ISBN は全て「不明」扱いで手入力必須。

### 雑な技術スタック候補

React Native (Expo) + expo-barcode-scanner + Open Library API + expo-sqlite、TestFlight & APK 直配布で公開

## 3. NoiseSleepLog

- カテゴリ: ガジェット
- 対象ユーザー: 睡眠が浅い気がするが高価なスマートウォッチを持たない人
- 一行で: RPi と USB マイクで夜の騒音タイムラインをグラフ化

### 解決する痛み

「なんか眠りが浅い」と感じているが原因不明。朝の車の音なのか、隣室の物音なのか、パートナーのいびきなのか、データがなければ改善策もとれない。高価なスマートウォッチは充電が面倒で続かない。マイクと RPi があれば夜間の騒音ログを取れるはずなのに、ちょうどいい OSS ツールが見当たらない。

### 1 週間で作るならこれ

- Raspberry Pi Zero 2W + USB マイクを枕元に置くだけのセットアップ
- 夜間の指定時間帯に 1 秒ごとの音量デシベルを SQLite に記録
- 朝 LAN 内 Web UI を開くと昨夜の音量タイムラインをグラフ表示
- 90 dB 超えた時刻を「騒音イベント」として赤くハイライト表示
- 録音データは保存せずデシベル値のみ記録（プライバシー配慮）

### なぜ雑か

音量だけで睡眠フェーズは判定しない（加速度センサーなし）。マイク感度は機種依存でキャリブレーションなし。リアルタイム表示は未対応。Web UI はローカル LAN 限定で外部公開は自己責任。Raspberry Pi の入手性問題は自力解決してほしいのだ。

### 雑な技術スタック候補

Python + PyAudio + SQLite + Flask + Chart.js、Raspberry Pi OS Lite 上で systemd サービスとして常時起動
