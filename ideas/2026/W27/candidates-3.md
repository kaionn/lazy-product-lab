## 1. ひとりブレストAI

- カテゴリ: Web (AI ツール)
- 対象ユーザー: アイデア出しで詰まりがちなひとりプロダクト開発者・フリーランス
- 一行で: AIに反論され続けてアイデアを10倍に広げる壁打ちツール

### 解決する痛み

ひとりでブレストするとすぐ同じところをぐるぐるして終わる。「誰かに壁打ちしてほしいけど気軽に頼める相手がいない」問題は、ひとり開発者なら週に何度も発生する。ChatGPT に投げると「良いですね！」と褒めるだけで批判してくれない。専用ツールとしてAIに「逆張り」「類似例」「制約除去」の3角度から畳み掛けてもらう体験がない。

### 1 週間で作るならこれ

- テーマを1行入力 → AI が「逆張り案」「実現済みの類似例」「制約を外したら？」の3角度から連続質問
- チャット形式で 5〜10 往復しながらアイデアを広げる
- セッション終了ボタンで「出てきたアイデア一覧」を Markdown で出力・コピー
- localStorage にセッション履歴を保存、過去のセッションを一覧から呼び出せる
- 「このアイデアを深掘り」ボタンで選択ブランチを新スレッドとして開始

### なぜ雑か

バックエンドは Next.js API Route + Claude API のみ。DB も認証も課金管理も一切なし。API キーは環境変数に直書きのみ対応で、複数ユーザーへの配布は非対応。会話履歴が長くなるとコストが青天井になる（コンテキスト長は 10 往復で強制打ち切り）。

### 雑な技術スタック候補

Next.js App Router + Anthropic SDK (claude-haiku-4-5) + Tailwind + localStorage、Vercel に 1 コマンドデプロイ

## 2. PR Narrator

- カテゴリ: 業務ツール (Web)
- 対象ユーザー: PR description を書くのが億劫な開発者
- 一行で: git diff 貼ったら日本語PR説明文が30秒で出る

### 解決する痛み

コードを書くより説明文を書く方が時間がかかる、という逆転現象がある。「diff を見ながら人間語に翻訳する」作業は地味に認知コストが高い。リモート開発では文章コミュニケーションが重要なのに、疲れた夕方に「変更概要」を書くのが毎回きつい。結果として「fix bugs」「update logic」のような読めない PR が量産される。

### 1 週間で作るならこれ

- テキストエリアに `git diff` の出力をペーストするだけ
- 「生成」ボタンで「概要」「変更した理由（推測）」「レビュアーが確認すべき点」の 3 セクションで出力
- Markdown 形式でそのまま GitHub PR body にコピーできるボタン
- 「もっと短く」「もっと詳しく」の 1 クリック調整
- 出力言語を「日本語 / English」で切り替え

### なぜ雑か

diff が 8000 文字を超えたら末尾を黙って切り捨て。APIキーはフロントエンドの環境変数から直接送信（個人使用前提）。バックエンドなし・完全静的サイトなのでレート制限なし（自己責任）。テストコードや lock ファイルの diff が混ざると出力の精度が下がる。

### 雑な技術スタック候補

Vite + React + Anthropic SDK + shadcn/ui 2〜3コンポーネント、Cloudflare Pages で無料ホスト

## 3. TokoMap

- カテゴリ: モバイル (PWA)
- 対象ユーザー: 「あと 2 時間ある」ひとり旅行者・散歩好き
- 一行で: 今の場所から「N分以内」で行ける観光スポットを地図表示

### 解決する痛み

旅行中「あと 1.5 時間あるけど何が見れる？」を直感的に調べる手段がない。Google Maps は距離優先で、「移動時間 XX 分以内のスポット」でフィルタする機能がない。候補を一つ一つ検索して時間を計算して…を繰り返すうちに時間を無駄にして結局カフェで休憩して終わる。

### 1 週間で作るならこれ

- 現在地を Geolocation API で取得（または地図タップで手動指定）
- 「移動時間」スライダー (15 / 30 / 45 / 60 分) で等時線 (isochrone) を計算
- OpenRouteService API で到達圏内エリアを Leaflet.js 地図にシェードで表示
- Overpass API (OSM) からエリア内の観光スポット・カフェ・公園を取得しピン表示
- スポットタップで「Wikipedia の概要」「Google Maps で開く」リンクを表示

### なぜ雑か

交通機関の乗り換えは考慮しない（徒歩・自転車モードのみ）。OSM のスポット情報は地域によって精度が大きく異なり、有名スポットが登録されていないこともある。等時線の計算は無料枠の OpenRouteService に依存しており、リクエスト数制限に引っかかるとエラーのまま止まる。PWA として保存してもオフライン非対応。

### 雑な技術スタック候補

Vite + Leaflet.js + OpenRouteService Isochrones API + Overpass API、Netlify で無料ホスト（ビルド 1 コマンド）
