## 1. TodoDecay

- カテゴリ: CLI
- 対象ユーザー: 大きめのレガシーコードベースを保守しているエンジニア
- 一行で: 放置されたTODO/FIXMEコメントを経過日数付きでランキング表示するのだ

### 解決する痛み

コードベースに `grep -r TODO` を打つと数百件ヒットするが、どれが「昨日書かれた現役のTODO」でどれが「3年前から放置されている地雷」なのか一目でわからない。結局全部無視されて誰も触らなくなる。棚卸ししたくても1件ずつ `git blame` するのは現実的ではない。古いTODOほど危険度が高いはずなのに、それを可視化する手段がない。

### 1 週間で作るならこれ

- リポジトリを再帰的に走査して `TODO` / `FIXME` / `HACK` を含む行を抽出
- 該当行ごとに `git blame -L` を実行し最終更新日時と著者を取得
- 経過日数でソートし上位20件をターミナルにテーブル表示（90日以上は黄色、180日以上は赤で強調）
- `--author` で著者フィルタ、`--json` で機械可読出力に対応
- `.tododecayignore` で除外パスを指定できるようにする

### なぜ雑か

ファイルごとに `git blame` を都度実行するので数千ファイル規模だと数分かかる（並列化なし）。行が移動・分割された場合の追跡は `git blame` の限界そのまま受け入れる。コメントが解決されて消えたかどうかの履歴追跡はしない。コメント記法の違いは正規表現一発でカバーし、言語別パーサーは作らない。

### 雑な技術スタック候補

Node.js + Commander.js + child_process(git blame呼び出し) + chalk(色付け) + npm packageとして配布

## 2. Bikeshed Buster

- カテゴリ: Bot (Slack)
- 対象ユーザー: エンジニアリングチームのSlackチャンネルで技術議論が長引くテックリード・PM
- 一行で: 決着しない議論スレッドを検知して「投票で決めよう」を自動提案するのだ

### 解決する痛み

「tabsかspacesか」「このライブラリでいいか」のようなスレッドが返信30件を超えても誰も「じゃあ多数決で」と言い出せず、数日間ダラダラ続く。全員が通知に振り回されて本来の作業に集中できない。誰かが議論を打ち切る役目を買って出るのは気まずいので、機械的にその役を肩代わりしてほしい。

### 1 週間で作るならこれ

- 監視対象チャンネルをApp設定でチャンネルごとにON/OFFできるようにする
- スレッド返信数が15件を超え、かつ2時間以内に「✅」リアクションが付いていない場合に検知
- 検知したら同スレッドに「そろそろ投票で決めませんか？」とBotが返信し、直近の発言から「〜案」「〜はどうですか？」を含む文を機械的に選択肢として抽出
- ユーザーは絵文字リアクション（1️⃣2️⃣3️⃣）で投票、24時間後に集計結果をBotがスレッド末尾に投稿
- `/bikeshed status` で現在監視中のスレッド一覧を表示

### なぜ雑か

選択肢抽出は特定のフレーズパターンにマッチした発言を機械的に拾うだけで意味理解はせず、誤爆（無関係な発言が選択肢に混ざる）はそのまま許容する。同時監視できるスレッドはワークスペースあたり20件までで超過分は無視。DM・プライベートチャンネルは非対応。投票結果に強制力はなく最終判断は人間任せ。

### 雑な技術スタック候補

Slack Bolt (Node.js) + Slack Events API + node-cron + Supabase(スレッド状態保存) + Railway

## 3. OnboardBuddy

- カテゴリ: 業務ツール (Web)
- 対象ユーザー: 新しいエンジニアが加わるたびにオンボーディング資料を手作業で更新しているテックリード
- 一行で: リポジトリのURLを貼るだけで初日セットアップ手順書が自動生成されるのだ

### 解決する痛み

オンボーディング資料はREADMEの片隅に古い手順が残ったままで、新メンバーは結局Slackで「これどうやって動かすんですか」と同じ質問を繰り返す。テックリードは毎回同じ説明を書くか口頭で伝えるかの二択で消耗する。リポジトリの中身自体は最新なのだから、そこから自動的に「初日ガイド」を作れれば説明の手間が省ける。

### 1 週間で作るならこれ

- GitHubリポジトリURLとread-only権限のPersonal Access Tokenを入力するだけのフォーム
- `package.json` / `README.md` / `.env.example` / `.github/workflows` の内容をGitHub API経由で取得
- Claude APIに投げて「必要なツールのインストール手順」「環境変数の設定方法」「起動コマンド」「最初に読むべきファイル」をMarkdownで生成
- 生成結果を専用URL（`/onboard/:id`）で常時閲覧できるようにして新メンバーに共有
- 「情報が古くなった」ボタンで手動リフレッシュ（再生成）のみ対応、自動更新はしない

### なぜ雑か

private repoの認証はPersonal Access Token直貼りでOAuth連携は作らない。生成された手順の正確性は保証せず、実際に実行して検証する機能もない。モノレポや複数言語混在プロジェクトは想定外（単一`package.json`前提）。生成後のガイドは新メンバー本人が編集することはできず、リード側が再生成するだけの一方通行にする。

### 雑な技術スタック候補

Next.js + GitHub REST API (Octokit) + Anthropic API (Claude) + Supabase(生成結果保存) + Vercel
