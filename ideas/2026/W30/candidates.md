## 1. ShipLog

- カテゴリ: Bot (Discord)
- 対象ユーザー: IndieHackers / Product Hunt 系の Discord コミュニティ管理者・メンバー
- 一行で: `/ship` 一発で今日の成果を鯖に流してサポートを集める

### 解決する痛み

インディー開発者の Discord では「作ったものをシェアしたい」という欲求があるが、テキストチャンネルに投げっぱなしだと数分で流れて誰にも見られない。Twitter/X に投稿するほどでもないが、コミュニティメンバーに「完成したよ」を伝えたい。Makerlog のようなシップ記録が Discord 内で完結すれば、コミュニティの熱量と帰属意識が上がる。現在は自前 Bot がなければこのユースケースを満たせない。

### 1 週間で作るならこれ

- `/ship <作ったもの> [URL]` コマンドで整形されたカードメッセージを #shiplog チャンネルに自動投稿
- 毎週月曜に「先週の ship まとめ」を自動投稿（全 ship を一覧 + 船を送った人をメンション）
- `/leaderboard` で今週 / 全期間の ship 数ランキング表示
- 投稿に 🚀 リアクションを付けると「応援カウント」が増えてランキングに反映
- 管理者が `/setup-channel #shiplog` で投稿先チャンネルを設定

### なぜ雑か

URL バリデーションなし（死んだリンクでも投稿できる）。スクリーンショットのサムネイル自動取得なし。カテゴリ分類（Web / App / ゲーム等）なし。週次まとめは固定テンプレートのみ。データは SQLite に保存でバックアップ手段なし。Railway 無料枠のスリープで最初のコマンドが遅延する。

### 雑な技術スタック候補

discord.py 2.x + sqlite3 + Railway 無料枠 (スリープあり)

## 2. StackTrace Linker

- カテゴリ: その他 (VS Code Extension)
- 対象ユーザー: Docker / コンテナ環境でデバッグするバックエンドエンジニア
- 一行で: コンテナ内スタックトレースをパスマッピングでクリック可能に変換

### 解決する痛み

`docker compose up` でエラーが出るとスタックトレースのパスが `/app/src/api/user.py:42` と表示されるが、ローカルの VS Code では `/Users/me/project/src/api/user.py:42` という別パスなのでクリックできない。VS Code のビルトイン TerminalLink はパスが一致するときしか機能せず、コンテナ・Lambda・CI ログを貼り付けたターミナルでは役に立たない。結果として毎回エラー行番号を手動検索しており、デバッグのリズムが崩れる。

### 1 週間で作るならこれ

- Python / Node.js / Go / Rust / Java の典型スタックトレースパターンを正規表現で検出
- `settings.json` にパスマッピングルールを設定（例: `"/app" → "${workspaceFolder}"`）
- マッチしたファイルパス部分をクリック可能なターミナルリンクとして登録
- クリックすると対象ファイルの指定行にカーソルジャンプ
- ホバーで対象コードの前後 3 行をプレビュー表示

### なぜ雑か

正規表現ベースのパターンマッチングのみで AST 解析なし。珍しいフレームワーク固有のエラー形式は非対応。ワイルドカードや glob パスマッピング未対応（完全文字列置換のみ）。ANSI カラーコードが混入した出力では検出精度が落ちる。VS Code の安定版最新リリースのみでテスト。

### 雑な技術スタック候補

TypeScript + VS Code Extension API (`vscode.window.registerTerminalLinkProvider`) + esbuild でバンドル + vsce でパッケージング

## 3. EstimateBattle

- カテゴリ: ゲーム
- 対象ユーザー: ソフトウェアエンジニア・「プログラミングの世界の雑学」が好きな人
- 一行で: 有名 OSS の「答え」を当てる開発者向けデイリートリビアゲーム

### 解決する痛み

「Linux カーネルって何行のコード？」「React って何年前から開発されてる？」というふとした問いは面白いが、調べると「ふーん」で終わる。それが「当てるゲーム」になれば、同じ情報でも何倍も記憶に残る。エンジニア向けのトリビアゲームはほぼ存在しない。Wordle のようにデイリー形式で毎朝習慣になれば、エンジニアコミュニティで口コミが広がりやすい。

### 1 週間で作るならこれ

- 有名 OSS 70 件のデータを手動収集（コード行数 / 初コミット年 / GitHub スター数 / コントリビュータ数）
- 「このリポジトリの総コミット数は？」など 5 種類の問題テンプレートからランダム出題
- 数値の近さでスコア計算（正解 ±10% で満点、±50% で半点、それ以外は 0 点）
- Wordle 風にデイリー 1 問のみで結果を絵文字でコピーして SNS シェア
- ローカルストレージで過去回答履歴・平均スコアを保持

### なぜ雑か

OSS データは手動収集のハードコードで API 連携なし（データが古くなっても自動更新されない）。初期問題数は 70 問のみ。難易度調整なし（全問同じ難易度）。正解範囲の ±10% ルールはプロジェクトのスケール無視。マルチプレイ・ランキングなし。デイリー問題はビルド時に日付シードで計算するだけ。

### 雑な技術スタック候補

Vite + Vanilla TypeScript + localStorage → GitHub Pages で静的ホスト（バックエンドなし、CI/CD は GitHub Actions）
