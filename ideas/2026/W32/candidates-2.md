## 1. 陽だまりログ

- カテゴリ: ガジェット
- 対象ユーザー: 在宅勤務でカーテンを開けずに一日を終えてしまうリモートワーカー
- 一行で: 机に置くだけで浴びた日光量を記録して夕方に「今日はまだ0分です」と教えてくれるのだ

### 解決する痛み

在宅勤務が続くと一日中室内で過ごし、日光をほとんど浴びないまま夜になっていることに自分では気づけない。気分の落ち込みや夜の寝つきの悪さが日光不足のせいだと分かっていても、毎日これを意識して記録する習慣は続かない。カーテンを開ける・少し散歩に出るといった行動は、その場で促されなければずっと後回しにされる。照度センサーが黙って計測し続けてくれれば、意識しなくても日光不足が数字として突きつけられる。

### 1 週間で作るならこれ

- ESP32 + 照度センサー(BH1750)をデスクに設置し1分ごとに照度を記録
- 屋外相当の明るさ(閾値1000lux以上)を検知した累積分数だけを「日光時間」としてカウント
- 小型OLEDディスプレイに本日の累積日光時間をリアルタイム表示
- 15時時点で日光時間が15分未満なら内蔵ブザーが1回鳴って散歩を促す
- 日ごとの日光時間合計をSDカードにCSV保存、あとでExcelで振り返れる程度

### なぜ雑か

太陽光と室内照明の光を厳密に区別しない（明るい照明下でもカウントされてしまう）。天候による自動補正はしない。スマホアプリやクラウド同期は作らずローカルのSDカードのみ。センサー1個の設置場所を前提にしており複数デスクや複数人利用には対応しない。ブザー音は1種類固定でカスタマイズ不可。

### 雑な技術スタック候補

Arduino IDE + ESP32 + BH1750 照度センサー + SSD1306 OLED + microSD カードモジュール + ブザー

## 2. 時差トルース

- カテゴリ: Web (SaaS)
- 対象ユーザー: 海外拠点のメンバーと定例MTGを組むリモートチームのPM・EM
- 一行で: メンバーのタイムゾーンを登録するだけで全員が起きてる時間帯を色分けして一発で見せてくれるのだ

### 解決する痛み

複数タイムゾーンのチームで会議を設定するたびに、各メンバーの現地時間をいちいち頭の中で変換して「この時間帯は誰かが深夜になっていないか」を確認するのに時間がかかる。World Time Buddyのような既存ツールは高機能すぎて毎回設定し直すのが面倒で、Slackのリマインダーだけでは全員の睡眠時間帯を俯瞰できない。チームのタイムゾーンを一度登録しておいて候補時間を選ぶだけで「誰が深夜か」が一目でわかれば十分。

### 1 週間で作るならこれ

- チームメンバーの名前とタイムゾーンをフォームで登録（最大10人）
- 24時間の横軸に各メンバーの現地時間帯を色分けバー表示（緑=稼働時間帯、赤=深夜）
- 候補の会議時間（自分のタイムゾーン基準）をクリックすると各メンバーの現地時刻と赤/緑判定を表示
- 「全員が緑になる時間帯」を自動でハイライトして候補として提案
- チームのURLを共有するだけで誰でも同じ画面を見られる（ログイン不要）

### なぜ雑か

稼働時間帯は「9時〜18時固定」の一律設定で個人ごとのカスタマイズは初期は不可。祝日・サマータイムの自動調整はしない（手動でタイムゾーンを直してもらう）。カレンダー連携（Google Calendar等）はせず表示のみ。10人を超えるチームは非対応。データはブラウザのlocalStorageのみでサーバー永続化はなく、URL共有もクエリパラメータでエンコードするだけ。

### 雑な技術スタック候補

Next.js + date-fns-tz + Tailwind CSS + URLクエリパラメータでの状態共有 + Vercel

## 3. コメント毒見役

- カテゴリ: Browser Extension
- 対象ユーザー: PRレビューやSlackでのフィードバックコメントがきつくなりがちなエンジニア
- 一行で: コメント送信前にAIがトーンをチェックして「ちょっときつめです」と教えてくれるのだ

### 解決する痛み

急いでいるときほどPRレビューのコメントが「これ直して」「なんでこうしたの」など素っ気なく・きつい言い方になりがちで、後で読み返して気まずくなる。書いている本人はきついと気づかず、送信してから相手の反応で初めて気まずさに気づくことも多い。送信ボタンを押す前の一瞬で「このトーン大丈夫？」と聞いてくれるだけで、言い直すきっかけになる。

### 1 週間で作るならこれ

- GitHub PRのレビューコメント欄・Slackのメッセージ入力欄にテキスト監視スクリプトを注入
- 送信ボタン押下時にAPIへ入力テキストを送信しトーン判定（「きつめ」「ふつう」の2択で十分）
- 「きつめ」判定なら送信を1回だけブロックし、警告バナーと「やわらかい言い方の例」を1案表示
- 「このまま送る」ボタンで確認後は送信を通す（強制はしない）
- 判定に使うAPIキーは拡張機能の設定画面でユーザー自身が入力（OpenAI APIキー等）

### なぜ雑か

判定は「きつめ/ふつう」の2値だけで細かいニュアンス分析はしない。日本語以外の言語は非対応。GitHubとSlack以外のツール（Notion, Linear等）には対応しない。誤判定（冗談や技術的に正確な厳しい指摘）もそのまま「きつめ」に倒れることがあるが許容する。オフラインでの動作は不可（API必須）。

### 雑な技術スタック候補

Chrome Extension Manifest V3 + Content Script (DOM監視) + OpenAI API (gpt-4o-mini) + chrome.storage (APIキー保存)
