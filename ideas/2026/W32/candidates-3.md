## 1. worksforme

- カテゴリ: CLI
- 対象ユーザー: 「自分の環境では動くのに他の人だと動かない」問題に何度も付き合わされるチームのエンジニア
- 一行で: 環境情報をスナップショットして2人分をdiffするだけで「動く/動かない」の違いを一発で洗い出すのだ

### 解決する痛み

「動きません」と言われて確認すると、node のバージョンが違う、global にインストールされてるパッケージが違う、環境変数が設定されていない、といった些細な差分で半日溶ける。毎回 `node -v`、`npm ls -g`、`env` の出力を手作業で見比べるのはあまりに非効率で、Slack で「env のスクショ送って」とお願いするのも気まずい。ワンコマンドで自分の環境を書き出して、相手のスナップショットと機械的に diff するだけで済ませたい。

### 1 週間で作るならこれ

- `worksforme snapshot` で node/npm/os/主要 global package のバージョン一覧と env 変数のキー一覧（値はマスク）を JSON 出力
- `worksforme diff snapshot-a.json snapshot-b.json` で差分だけを色分け表示
- 主要ランタイム（node, python, ruby）のバージョン検出のみ対応
- `.env` はキー名だけ比較（値は比較せず、存在有無のみ判定）
- 結果を Markdown 形式でも出力できるようにして Slack に貼れるようにする

### なぜ雑か

対応する OS・パッケージマネージャの組み合わせは限定的（brew, apt 等の差異までは見ない）。Docker コンテナ内外の差異は検出しない。値そのものの比較はしない（セキュリティ上、存在有無だけを見る）。3 人以上の同時 diff には対応せず、常に 2 ファイル比較のみに割り切る。

### 雑な技術スタック候補

Node.js CLI (commander) + execa（バージョン取得） + diff (npm) + chalk

## 2. 忘れ物ドア番

- カテゴリ: ハードウェア
- 対象ユーザー: 家を出てから「あ、鍵/財布/社員証忘れた」と気づいて引き返す一人暮らし・時間に追われる人
- 一行で: 玄関にセンサーを置くだけで鍵・財布・社員証が出発時に無いとブザーで教えてくれるのだ

### 解決する痛み

家を出た瞬間に鍵や財布を忘れたことに気づき、駅の改札前や電車の中で引き返す羽目になる。忘れ物は毎回違うわけではなく大体決まった2〜3個（鍵・財布・社員証など）なのに、玄関を出る前に確認する習慣がどうしても身につかない。スマホのリマインダーは家を出る前に開かないので意味がなく、玄関を通過する瞬間に「無いものがある」と物理的に気づかせてくれる仕組みが欲しい。

### 1 週間で作るならこれ

- 鍵・財布・社員証それぞれに安価な BLE タグを取り付け
- 玄関に置いた Raspberry Pi Zero WH が BLE スキャンで各タグの RSSI を1秒ごとに監視
- ドア開閉を検知する磁気スイッチと連動し、ドアが開いた瞬間にタグの近接判定を実行
- 未検出のタグがあればブザーと LED で警告（タグ名を OLED に表示）
- 誤検知を避けるため「出発モード」は手動ボタンで明示的に ON にしてから玄関を通過する運用

### なぜ雑か

BLE RSSI による距離判定は精度が低く、近くにあっても稀に検知漏れする。タグの電池残量監視はしない。複数人が同時に出発する場合の個人別判定はできず、家族全員のタグをまとめて監視するのみ。外出モードの自動検知（GPS 連動など）はせず、必ず手動ボタンを押す運用を前提とする。

### 雑な技術スタック候補

Raspberry Pi Zero WH + BLE タグ + bleak (Python BLE スキャン) + リードスイッチ + ブザー + SSD1306 OLED

## 3. 請求書追跡くん

- カテゴリ: SaaS
- 対象ユーザー: 個人で複数クライアントに請求書を出しているフリーランス・小規模事業者
- 一行で: 請求書の支払期日を登録するだけで期日を過ぎたらクライアントへ自動で催促メールを送ってくれるのだ

### 解決する痛み

フリーランスは請求書を送った後、いつ入金されるかを Excel や記憶に頼って管理していることが多く、支払いが遅れているクライアントに催促するタイミングを逃しがちで、催促メール自体も「失礼にならないか」と身構えて後回しにしてしまう。気づけば入金が1ヶ月以上遅れていて、生活費が回らなくなってから慌てて連絡するはめになる。人間関係を壊さない程度の丁寧な催促文面を、期日通りに機械的に送ってくれるだけで気持ちが楽になる。

### 1 週間で作るならこれ

- 請求書ごとにクライアント名・金額・支払期日・クライアントのメールアドレスを登録するフォーム
- 支払期日を過ぎたら1日1回 cron でチェックし、未入金フラグが立っている請求書に自動でリマインドメール送信
- 催促メールは「期日3日前」「期日当日」「期日超過7日ごと」の3段階でテンプレート文面が徐々に強くなる
- 入金確認後は自分でボタンを押して「入金済み」にする（銀行 API との自動連携はしない）
- ダッシュボードで未入金の合計額と件数を一覧表示

### なぜ雑か

銀行口座や Stripe との入金自動照合はせず、入金確認は手動ボタンのみ。催促メール文面は3段階固定のテンプレートで、クライアントごとのカスタマイズはできない。通貨は日本円のみ対応。請求書 PDF の発行機能自体は作らず、既存の請求書を前提に期日と金額だけを登録する管理ツールとして割り切る。

### 雑な技術スタック候補

Next.js + Supabase (DB + pg_cron) + Resend（メール送信） + Vercel
