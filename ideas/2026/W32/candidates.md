## 1. タブ罪悪感メーター

- カテゴリ: Browser Extension
- 対象ユーザー: 「あとで読む」タブを開いたまま何十枚も溜め込んでしまうエンジニア・リサーチャー
- 一行で: 開きっぱなしのタブに罪悪感ポイントが貯まっていって数字で殴られるのだ

### 解決する痛み

気づけばタブが 40 枚を超えていて、どれも「あとで読む」つもりだったのに一つも読んでいない。整理系の拡張は「読了時間を計算して並べ替える」など優しすぎて、結局後回しにする言い訳を与えるだけで閉じる決断につながらない。罪悪感を数字にして毎日目に入れば、さすがに嫌になって閉じる。ツールバーのバッジがどんどん赤くなっていくのを見たくない、という気持ちに賭ける。

### 1 週間で作るならこれ

- 拡張機能インストール時・新規タブ作成時にタブごとの「開いた時刻」を記録
- 経過時間から罪悪感ポイントを計算（1 時間 = 1pt、24 時間超からは倍々で増加）
- ツールバーアイコンのバッジに全タブ合計の罪悪感ポイントを常時表示
- ポップアップに罪悪感ランキング TOP5 を表示、各タブに「今すぐ閉じる」ボタン
- 1 日 1 回、正午に「今日のワースト5」を chrome.notifications で通知

### なぜ雑か

タブグループ・ピン留めタブも区別せず全部同列に罪悪感カウントする。ポイント計算式は経過時間だけの超簡易版で、閲覧履歴やスクロール量は一切見ない。Service Worker がスリープ復帰するたびに多少の誤差が出ても許容する。複数ウィンドウ・複数端末間でのタブ状態同期はしない（そのブラウザだけで完結）。

### 雑な技術スタック候補

Chrome Extension Manifest V3 + chrome.tabs API + chrome.storage.local + chrome.notifications + chrome.action (バッジ表示)

## 2. ケッテイログ

- カテゴリ: Bot (Slack)
- 対象ユーザー: 意思決定がSlackのスレッドに埋もれて後から探せなくなるスタートアップ・リモートチームのPM/エンジニア
- 一行で: 決定メッセージに絵文字をつけるだけで意思決定ログが自動で溜まっていくのだ

### 解決する痛み

「なんでこの実装にしたんだっけ」を確認しようとして、Slack の検索窓に思いつく限りのキーワードを打ち込んでは目的のスレッドが見つからず 10 分溶かす。議事録は書く習慣が続かないし、Notion に手動転記するのは面倒で誰もやらない。決定はいつもチャットの中で自然発生し、そのまま流れて消えていく。決定した瞬間に残す仕組みがあれば、探す手間そのものがなくなる。

### 1 週間で作るならこれ

- メッセージに📌（決定リアクション）が付いたら Slack Events API (reaction_added) で検知
- 対象メッセージ + 直前後 3 件のスレッド文脈を取得
- 「日時・発言者・チャンネル・決定内容・元メッセージへのパーマリンク」を Notion DB に自動追記
- 週1回月曜朝に、直近1週間の決定ログをダイジェストとしてチャンネル投稿
- `/decision-search キーワード` コマンドで過去ログを検索して Slack に返す

### なぜ雑か

📌 を付け忘れたら記録されない（AI による自動検知はしない）。文脈取得は前後3件固定で、長い議論は途中で切れる。書き込み先は Notion 一択（Google Sheets 等の切り替えは作らない）。複数チームでの権限管理・重複防止は考慮しない。

### 雑な技術スタック候補

Slack Bolt (Node.js) + Slack Events API + Notion API + Railway でホスト

## 3. 情報賞味期限くん

- カテゴリ: CLI
- 対象ユーザー: 古いブログ記事やStack Overflow回答を参考にコードを書こうとしているエンジニア
- 一行で: 記事のURLを渡すだけで載っているバージョン情報がどれだけ賞味期限切れか教えてくれるのだ

### 解決する痛み

検索して出てきた解説記事の通りに `npm install` したらエラーの山、よく見たら3年前の記事でバージョンがとっくに変わっていた、という事故が定期的に起きる。記事の日付は見ても、それが今のライブラリのバージョンとどれくらい乖離しているかは結局自分でnpmを叩いて確認するしかない。URLを貼るだけでその面倒な確認を肩代わりしてほしい。

### 1 週間で作るならこれ

- `staleness-check <URL>` でHTMLを取得しテキスト抽出
- 正規表現で `npm i pkg@1.2.3` `pip install pkg==1.2.3` 形式のバージョン言及を検出
- npm registry API / PyPI JSON API で最新バージョンを取得し記事内バージョンと比較
- メジャーバージョン差が2以上なら⚠️付きで警告表示、パッケージごとに一覧テーブル出力
- OGPの `article:published_time` があれば「この記事は約N年前」も併記

### なぜ雑か

正規表現に一致しない書き方（バージョン省略・対話形式コード）は無視される。npm と pip 以外のエコシステム（Go, Rust, Ruby等）は非対応。数字の誤検出（バージョンっぽいだけの別の数値）は放置。SPAでレンダリングされるページは取得に失敗してエラーで終わる。deprecated情報やbreaking changesの中身までは見ず、メジャーバージョン差だけで判定する。

### 雑な技術スタック候補

Node.js CLI (commander) + node-fetch + cheerio (HTML解析) + npm registry API + PyPI JSON API
