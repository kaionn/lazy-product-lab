## 1. ヤバい条項ハイライトくん

- カテゴリ: Web (AI ツール)
- 対象ユーザー: 業務委託契約書を毎回自分でチェックしているフリーランスエンジニア・デザイナー
- 一行で: 契約書のテキストを貼るだけで危ない条項をハイライトして理由を教えてくれるのだ

### 解決する痛み

フリーランスは業務委託契約書を毎回「なんとなく」読んで捺印しているが、損害賠償無制限や秘密保持の異常に広い範囲、支払サイトが90日など不利な条項を見逃しがちである。弁護士に毎回相談する予算も時間もなく、結局「まあ大丈夫だろう」で済ませてしまう。契約後にトラブルになって初めて気づくケースも多い。テキストを貼るだけで機械的に危険信号だけ拾ってくれれば、契約前の最後のチェックとして十分機能する。

### 1 週間で作るならこれ

- 契約書テキストをペーストするテキストエリア1枚のWebフォーム
- 「フリーランス実務でよく問題になる条項パターン一覧」をプロンプトに埋め込みLLMで該当箇所を抽出
- 該当箇所を原文ハイライト＋「なぜ危ないか」を一言で表示
- 危険度は「要注意 / 一応確認」の2段階だけで表示（詳細スコアリングはしない）
- 結果をコピーできるボタンのみ用意（保存・履歴機能なし）

### なぜ雑か

法的アドバイスではなく「機械的なパターンマッチ＋LLM解釈」に過ぎないと免責事項で明示するだけで法務監修はしない。対象は日本語の業務委託契約のみで、英文契約や不動産・金融など特殊業界の契約は非対応。貼り付けたテキストはDBに保存せず一時保持のみとし、暗号化などのセキュリティ対応は最低限。誤検知や見逃しがあっても補償はしない前提で割り切る。

### 雑な技術スタック候補

Next.js + Claude API + Vercel + localStorage（貼り付け内容の一時保持のみ、DBなし）

## 2. 翻訳キー幽霊検査官

- カテゴリ: CLI
- 対象ユーザー: 多言語対応しているWebアプリ・モバイルアプリの開発者
- 一行で: ロケールJSONとソースコードを渡すだけで使われてない翻訳キーと足りない翻訳キーを一覧にしてくれるのだ

### 解決する痛み

i18nライブラリを入れて機能追加を重ねるうちに、`locale/ja.json` や `en.json` の中に「もう使われていないキー」が溜まっていく。逆に開発中に `t('new.key')` と書いたのにJSONへの追加を忘れて、本番で素のキー文字列がそのまま表示される事故も起きる。目視でJSONとコードを突き合わせるのは数百キーになると現実的でなく、レビューでも見落とされがちである。CIに組み込めるくらい軽量なチェッカーがあれば安心してリファクタできる。

### 1 週間で作るならこれ

- ソースディレクトリとlocaleファイルのパスを引数に取るCLI
- `t('xxx')` や `i18n.t("xxx")` などよくある呼び出しパターンを正規表現で走査してキー使用箇所を収集
- 各localeファイルのキー一覧と突き合わせて「未使用キー」「コードにあるが未定義のキー」を分けて一覧表示
- 言語間でキーセットが食い違っている場合（`ja.json` にあって `en.json` にない等）も警告
- 未使用・未定義キーがあればexit codeを非0にしてCIで落とせるようにする

### なぜ雑か

対応するi18n呼び出しパターンは主要な2〜3種類の書き方のみで、動的キー生成（`t(\`prefix.${var}\`)`）は検出できない。ネストしたJSONのキー階層は3階層までしか正しく辿らない。TypeScriptの型定義との連携はなし。動的キーを誤って未使用扱いする問題は「除外リストで手動対応してください」とREADMEに書いて逃げる。

### 雑な技術スタック候補

Node.js + Commander + fast-glob + 正規表現ベースの走査（AST解析はしない）+ GitHub Actions組み込みサンプル同梱

## 3. 会議室ゴースト占有番人

- カテゴリ: ハードウェア
- 対象ユーザー: 会議室が慢性的に埋まっている・ダブルブッキングされがちなオフィスの総務・従業員
- 一行で: ドア横の人感センサーとカレンダーを突き合わせて予約なしの居座りや無断キャンセルを光と通知で教えてくれるのだ

### 解決する痛み

会議室を予約したのに前の会議が延長していて入れない、逆に予約されているのに誰も来ておらず空いているのに使えないと思われて放置される、という2つの「会議室あるある」が同時に起きている。総務がいちいち見回って確認するのは現実的でなく、社員はカレンダーと実際の使用状況を突き合わせる手段を持たない。ドアの外に「今ここで何が起きているか」が一目でわかるランプがあれば、居座りにも無駄な空室にも即座に気づける。

### 1 週間で作るならこれ

- ドア上部にESP32＋人感センサー（PIR）を設置し在室有無を検知
- Google Calendar APIで該当会議室リソースの予約状況を5分おきに取得
- 「予約あり＋人あり」は緑、「予約なし＋人あり」（ゴースト占有）は赤点滅、「予約あり＋人なし」（無断キャンセル濃厚）は黄色でドア外のLEDリングを点灯
- 赤点滅が15分以上続いたら総務のSlackチャンネルへ自動通知
- 会議室1部屋につき1台設置するシンプル構成（複数拠点対応なし）

### なぜ雑か

人感センサーは人数や誰がいるかまでは判別できず「1人でも複数人でも同じ扱い」にする。ドア外からの反射などによる多少の誤検知は許容する。カレンダーAPIの認証はGoogle Workspace限定でOutlookは非対応。LEDリングの取り付けは両面テープでドア枠に貼るだけの簡易施工とし、電源はUSB給電でバッテリー内蔵なし。

### 雑な技術スタック候補

ESP32 + PIRセンサー + WS2812 LEDリング + Google Calendar API + Slack Webhook + Arduino IDE
